# v0.32.1 - 2026-10-31

> 🪆 **给拓扑排序换一种写法，两种实现并存**。v0.32.0 的 `tp_sort` 把「插件、依赖、排好没」拆成两个字典加一个输出列表，状态散在三处。这一版新增 `PluginTopologyRuntime` 把三者收进一个对象，并据此写出 `tp_sort2`。**`tp_sort2` 目前没有调用方**，加载流程仍然走 `tp_sort`，两者在全部用例上输出一致。

## Added

- **`core/plugin/models/topology_runtime/`**：新增子包，暴露 `PluginTopologyRuntime`。字段是 `plugin` / `dependences` / `index`，方法 `is_null_dependences` / `is_sorted` / `remove_dependence` / `mark_sorted`。
- **`PluginTopologyRuntime.build(plugin)`**：从 `Plugin` 构造，依赖列表是 `list(plugin.metadata.dependences)` 的副本，不回写元数据。
- **`tp_sort2`**（`core/plugin/loader.py`）：用 `PluginTopologyRuntime` 的拓扑排序。`index` 记「第几轮被解锁」，末尾按 `index` 升序输出，同层内按插件名。
- **`models/__init__.py`** 导出 `PluginTopologyRuntime`。

## Note

- **`is_sorted` 就是 `index is not None`**：不再单独存 `sorted` 布尔字段，「排好了」和「第几层」是同一件事，一个字段足够。
- **`remove_dependence` 会移除所有同名依赖**：`[dep for dep in self.dependences if dep.name != name]`。元数据层已经挡住重复声明，所以正常情况下一次只会命中一个；即使绕过 pydantic 硬塞重复依赖，这里也一次删干净。
- **同层顺序仍然由入口的 `sorted` 钉死**，与 `tp_sort` 相同。
- **`tp_sort2` 比 `tp_sort` 慢**：每轮对「待摘除的插件 × 所有 runtime」各扫一遍依赖列表，N=500 时约 5 倍。当前 18 个插件是微秒级，没有优化的必要。
- **两者在「同名插件」上行为不同**：`tp_sort` 用字典存插件，同名会被覆盖成一个；`tp_sort2` 用列表，两个都保留。插件名来自目录名，正常不会重复。
