# v0.30.2 - 2026-10-29

> 💬 **私聊的首块回复不再走 `event.reply`**。`reply` 在私聊里带的那些引用 / 样式看着太丑，私聊改成和后续块一样用 `easier_send` 直接发；群聊保持原样。

起因是 `on_message` 里那条判断只看了下标：

```python
if index == 0:
	await event.reply(content_part)
	continue
```

群聊里首块带引用是有用的（能看出在回谁），但私聊里没有意义，只是把气泡搞得花里胡哨。于是条件收紧成同时要求群聊，私聊的每一块（包括首块）都落到 `easier_send`。

## Changed

- `main.py` 的 `on_message`：走 `event.reply` 的条件由 `index == 0` 改为 `index == 0 and is_group`；私聊的所有块统一走 `utils.easier_send`（`to_group=False`）。

## Note

- 群聊行为不变：首块仍用 `event.reply` 带引用，后续块用 `easier_send`。
- 打字延迟、切块逻辑、`split` / `typing` 配置均未改动。
