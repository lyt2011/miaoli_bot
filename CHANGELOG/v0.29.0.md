# v0.29.0 - 2026-10-29

> 🧱 **子插件框架整体重写**。`core/plugin_loader.py` 删除，换成 `core/plugin/` 下的 `Loader` + `Plugin`；17 个子插件的 `plugin.toml` 全部改名为 `metadata.toml`；两个注册器迁入 `core/registries/`；每个子插件的 `on_close` 补上对称卸载。

`plugin.toml` 这个名字让人以为里面是「插件本体」，实际装的是**元信息**（名字、入口类、描述、依赖）。改叫 `metadata.toml` 之后，元信息、入库模板 `config.example.yaml`、运行期配置 `config.yaml`、给 ncatbot 看的 `manifest.toml` 四者职责不再混淆。

原来的 `PluginLoader` 一个类干了四件事：扫目录、把文件夹注册成 Python 包、读配置、调生命周期。`Loader` 只留下"编排"（`prepare_plugins` / `load_plugins` / `unload_plugins` 三段），单个插件的造包、实例化、注入、生命周期全部交给 `Plugin`。

最实际的一处是卸载：处理器注册表此前只能加不能减，插件卸载后重新加载会把同一批节点再挂一遍 —— 实测 `load → unload → load` 让 handler 从 27 涨到 54。现在每个子插件在 `on_close` 里用 `HandlerRegistry.remove_*()` / `ToolRegistry.remove()` 把挂上去的东西摘回来，三轮循环稳定在 27。

## Added

- `core/plugin/`：新子插件框架 —— `loader.py`（`Loader`）、`plugin.py`（`Plugin`，负责 `from_path` / `load` / `build_instance` / `activate` / `deactivate` / `unload`）、`models/`（`Dependence` / `Specifier` / `PluginMetadata`）、`errors/`（`BasePluginError` / `EntryClassNotFound` / `MetadataMissingError` / `NotAPackageError`）。
- `core/registries/__init__.py`：导出 `ToolRegistry` / `HandlerRegistry`。
- `api/registry_ops.py`：`get_handler_registry()` / `get_tool_registry()`，子插件统一从 `miaoli_bot.api` 取注册器，不再由框架构造注入。
- `HandlerRegistry.remove(event, node)` 与 11 个 `remove_*`：注销事件处理器，与已有的 `on` / `on_*` 一一对应。
- `HandlerRegistry.on(event, node, priority)`：通用注册入口，11 个 `on_*` 全部转发到它。
- `Loader` 的 `mark_prepared` / `mark_erred` / `mark_loaded` / `is_prepared` / `is_erred` / `is_loaded`：把 `_prepared` / `_erred` / `_loaded` 三个容器的读写收口。
- `loader.py` 底部的 `safe_load_plugin` / `safe_activate_plugin` / `safe_deactivate_plugin` / `safe_unload_plugin`：把生命周期调用包在 try 里，失败记日志并返回 `False`。
- `plugins/ob11_adapter/core/parser_registry.py`（`ParserRegistry`）与 `plugins/ob11_adapter/api/parser_registry_ops.py`（`get_parser_registry`）。
- `plugins/qq_platform_tools/data/ob11_segments.md`：OB11 发送侧各消息段的 `data` 字段清单（必填与否、互斥关系、字段名陷阱、组合示例）。

## Changed

- `core/registry.py` → `core/registries/handler_registry.py`，类 `Registry` → `HandlerRegistry`：改为无状态，注册时按 key 从 `SHARE_STORE` 现取 `GraphPipeline`，不再构造时注入 pipeline / tools；方法 `_register_node` → `register_handler`。
- `core/tool_registry.py` → `core/registries/tool_registry.py`。
- `consts/share_store_keys.py`：`TOOL_REGISTRY` 的 key 改为 `miaoli_bot/core.registries.tool_registry`，新增 `HANDLER_REGISTRY`（`miaoli_bot/core.registries.handler_registry`）。
- `core/__init__.py`：导出 `ToolRegistry` / `HandlerRegistry` / `Loader`。
- 17 个子插件的 `plugin.toml` → `metadata.toml`，字段从 `enter_file` / `enter_class` 改为 `name` / `entry_class` / `description` / `dependences`；`entry_class` 是点号路径（`main.IntentRecognition`、`a.b.Demo`，入口类在 `__init__.py` 里时只写类名），`PluginMetadata` 随之去掉 `entry_file`。
- `_plugin_in_dev/` → `core/plugin/`（该目录此前未入 git，本次首次提交）。
- `protocols/abc/plugin.py`：`PluginProtocol` 删掉 `__init__(config, registry)`，插件不再自己接注册器与配置，注册器走 `miaoli_bot.api`、配置由框架注入 `self.config`。
- 17 个子插件的 `main.py`：`self.registry.on_*` → `get_handler_registry().on_*`；`on_close` 补上对应的 `remove_*` / `ToolRegistry.remove(..., ignore_error=True)`，顺序统一为"先摘挂载，再 `store_drop` 内部键"。
- `models/config/sub_plugin.py`：`load_from` 从 `Optional[Path]` 改为 `List[Path]`（`default_factory=list`），支持多个插件目录；缺省空列表即不加载任何子插件。
- `config.yaml` / `config.example.yaml`：`sub_plugin.is_enable` → `enable`（原键名被 pydantic 当未知键静默丢弃），`load_from` 改成列表。
- `main.py`：`Registry(pipeline=..., tools=...)` 构造 → 直接把 `HandlerRegistry()` 放进 `SHARE_STORE`；loader 调用改为 `prepare_plugins()` → `load_plugins()` / `unload_plugins()`。
- `plugins/ob11_adapter`：`api/registry.py` → `core/parser_registry.py`，类 `Registry` → `ParserRegistry`（它注册的是 parser，不是 bot）；`main.py` 里 `bot_registry` → `handler_registry`、`registry` → `parser_registry`；`consts` 的 `REGISTRY` → `PARSER_REGISTRY`。

## Removed

- `core/plugin_loader.py`：能力被 `core/plugin/` 完整接替，不做兼容层。
- `Registry.register_tool`：工具注册只走 `ToolRegistry`，事件只走 `HandlerRegistry`。
- `PluginLoader.PACKAGE_PREFIX`：新框架直接用子插件目录名当包名，不再加前缀。

## Fixed

- `ToolRegistry.remove(name, ignore_error=True)` 在工具不存在时仍然抛 `KeyError` —— 前一行只是跳过了友好报错，真正的 `self._tools.pop(name)` 没有默认值。插件 `enable: false` 时没有注册过工具，卸载再摘就会炸。
- `bash` 工具超时后只 `kill` 掉 `/bin/sh`，真正的子进程脱管成孤儿继续跑（`pip install` 时代实测卡十分钟）。改为 `start_new_session=True` 让子进程自成进程组，只在超时/异常路径 `os.killpg` 整组杀；同时删掉 `finally` 里那句在成功路径也会执行、毫无意义的 `proc.kill()`。（issue #3）

## Note

- `tp_sort()` 仍是占位实现（直接 `list(plugins)` 返回），真正的拓扑排序未写；`unload_plugins` 的 `[::-1]` 依赖它返回"依赖在前"。
- `Loader` 只对"加载失败"做跳过记账（`_erred`），失败插件的半成品状态由插件自己的 `on_close` 负责清理，框架不代劳。
- `plugins/` 下 `intent_recognition` / `mcp_adapter` / `miaoli_bot_adapter` 的 `config.yaml` 不入库，本地缺配置时这三个会以 `ValidationError` 失败，属预期。
