# v0.42.0 - 2026-11-09

> 🧱 **一个通道一次把货全交出来，图一条一条跑**。`BaseChannel.drain()` 的返回从「一条消息」变成「一批消息」（一个会话一条），`tick` 拿到手之后不再 `gather` 并发，改成串行逐条跑 —— 并发跑图的日志读不出归属，串行靠「块的位置」就能对上号（破坏性）。

这一版是 0.41.0 那条链路的收尾。0.41.0 把通道抽象、`thread_id`、锁都摆正了，但入口还留着一个形状问题：`drain()` 一次只交一个会话，于是渠道里积压 N 个群就得等 N 轮 `tick.interval` —— 实测一个私聊消息等了 3 分 13 秒，其中真跑图 17 秒，剩下 2 分 56 秒全在排队。改完的结果是「一轮取空、一轮跑完」，代价从「排队」换成「串行」。

## Added

- `main.py` 新增模块级别名 `ChannelDrainResult = Dict[BaseChannel, List[BaseChannelMessage]]`，`_drain_channels` / `_run_channel_graphs` 都拿它当注解，省得每处重写一遍泛型。

## Changed

- **`BaseChannel.drain()` 的返回类型**：`BaseChannelMessage` → `List[BaseChannelMessage]`。一个通道一次交回它在缓冲里的全部会话，每个会话一条，条内保持「旧 → 新」、条间按各自最旧的那条事件排序，全空时返回 `[]`（不是一条空消息）。协议只改形状，去重仍然归通道自己。
- **`ChannelSurface.batch_drain()` 的映射值**：`{渠道: 渠道消息}` → `{渠道: List[渠道消息]}`，`_drain_c` 的元组同步；跨通道仍是 `gather` 并发 + 每通道一路 `wait_for`，异常照旧只落在自己那一路。
- **跑图从并发改成串行**：`tick` 里原来的 `coros` 列表 + `asyncio.gather(return_exceptions=True)` + 事后遍历 `results` 记错误的循环被 `_run_channel_graphs` 取代，两层 `for` 逐条 `await`，异常就地 `logger.exception`，正常收尾打 `debug`。
- **`tick` 拆成四段**：`on_tick` 只剩「等 → 取 → 跑 → 记」四行，细节分到 `_wait_atick`（等事件并清理标记）、`_drain_channels`（注册器转 surface 后取空）、`_run_channel_graphs`（串行跑图）。
- **日志带上会话身份**：跑图完成 / 主动中断 / 跑图异常 / 返回未匹配对象这四处都从「渠道 `name`」扩成「渠道 `name` + `thread_id`」—— 串行之后同一渠道下多条会话的日志能分开看。
- **`config` 从循环外挪进循环内**：每轮重新 `SHARE_STORE.recall(PLUGIN_CONFIG)`，改配置下一轮就生效，不用重启。

## Removed

- `tick` 里的 `coros` 列表、`asyncio.gather(..., return_exceptions=True)` 调用，以及事后遍历 `results` 判 `isinstance(result, Exception)` 的那段汇总循环。
- `tick` 开头那个取了却没用上的 `channel_registry` 局部变量 —— 改为在 `_drain_channels` 调用处现取。

## Fixed

- **`core/graph_runner.py`：`ainvoke` 把首参写成了关键字** —— `pipeline.ainvoke(state=state, thread_id=…, context=…)` 改为 `pipeline.ainvoke(state, thread_id=…, context=…)`。`ainvoke` 的首个参数是位置参数（`input`），按 `state=` 传会直接 `TypeError`，整张图连一次都跑不起来。

## Note

- **这是破坏性变更**：任何实现 `BaseChannel` 的渠道都得把 `drain()` 改成返回列表。平级的 `miaoli_qq_channel` 要同步改（它的 `QQChannel.drain()` 里原本还有「取出一个会话、把剩下的写回缓冲」的逻辑，改完这些逻辑整段消失）。
- **`INVOKE_LOCKS` 仍然按 `thread_id` 分**：同会话串行靠锁，一轮里的先后靠 `tick` 的串行循环，两者不重叠，也不互相替代。
- **串行的代价**：N 个会话的耗时叠加，最坏 `N × graph.atimeout` 才走完一轮。换来的只有一样东西 —— 日志读得懂。
- 为什么不用并发：框架 `ncatbot/utils/logger/formatter.py` 的 `FILE_FORMAT` 只打 `%(message)s`，`BoundLogger.bind()` 的 `extra` 根本不落盘；子插件各用独立 `get_log(name)`、也没有 thread 上下文。并发跑图时日志会说谎，串行时「块的位置」就是会话身份，零标注。
