# v0.29.1 - 2026-10-29

> 🧱 **修 `on_close` 的卸载顺序**。0.29.0 先清空共享容器、再卸子插件，导致 17 个子插件的 `on_close` 在取注册器时全部 `KeyError`。

子插件从 0.29.0 起要在 `on_close` 里用 `HandlerRegistry.remove_*()` / `ToolRegistry.remove()` 把挂上去的节点与工具摘回来，而这两个注册器是从 `SHARE_STORE` 现取的。`main.on_close` 却仍然是先 `drop(TOOL_REGISTRY)` / `drop(HANDLER_REGISTRY)`，子插件再去 `recall` 就是 `KeyError: 'miaoli_bot/core.registries.handler_registry'` —— 服务器重启日志里 17 个子插件一整排「停用失败」，`web_search` 的 aiohttp 会话也因此没关掉（`Unclosed client session`）。

顺序改成：先 `unload_plugins()` 卸子插件，再 `cpa.close()` 关 checkpointer，最后才 `drop` 共享容器里的键。进程整体退出时这些注册最终会随进程消失，所以这次没有实际后果，但热重载场景下会留下没摘干净的挂载点，日志也全是红的。

## Fixed

- `main.py`：`on_close` 里 `await self.plugin_loader.unload_plugins()` 与 `await self.cpa.close()` 挪到所有 `SHARE_STORE.drop(...)` 之前，并在上方注明原因（子插件的 `on_close` 离不开注册器）。

## Note

- 子插件缺少 `config.yaml` 时，`self.config` 是 `None` 而不是空字典（0.29.0 的 `Plugin._prepare_config` 不再兜 `{}`）。`PluginConfig.model_validate(None)` 会直接 `ValidationError`，插件被判「激活失败」。部署时发现服务器上 `ob11_adapter` / `miaoli_bot_adapter` 一直没有 `config.yaml`（旧 `PluginLoader` 给 `{}` 吃默认值所以没暴露），现在必须由 `config.example.yaml` 各复制一份。

## Docs

- `README.md`：插件卸载流程那一条改写为「先卸子插件 → 关 checkpointer → 再清共享容器」，并说明为什么不能倒过来；子插件约定补上「运行环境必须有 `config.yaml`，缺了 `self.config` 是 `None`」。
