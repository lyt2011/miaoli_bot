# v0.18.2 - 2026-10-17

> 🐛 **修复 `tool_attachment_fixer` 的 flush 时机缺陷（[issue #1](https://github.com/lyt2011/miaoli_bot/issues/1)）**。0.18.1 记录的两个缺陷中，导致 `400` 硬崩的那个本版修掉：`pending` 原本在「遇到任何非目标消息」时倒出，而「目标」的判定条件包含「content 必须是 list」，于是同批工具里只要有一个返回 `str`，就会被误判成边界消息、把附件 `HumanMessage` 提前插进 `ToolMessage` 序列中间。

## Fixed

- **`nodes/fix_attachment.py` 的 flush 时机**：循环改为 `if / elif / else` 三路分流 —— ① 非 `ToolMessage` 才是真正的边界，此时 flush `pending`；② `content` 为 `str` 的 `ToolMessage` **直接原样追加、不 flush**（它没有块可搬，但仍是工具返回，不能当作边界）；③ 其余 `ToolMessage` 才改写 content 并把原始块攒进 `pending`。附件统一落在段末，`AI(tool_calls)` 之后的 `ToolMessage` 序列不再被打断。
- **内容丢失**：改写前先 `raw_content = list(message.content)` 存下原始块，再覆盖 `message.content`。此前若顺序写反（先覆盖再取值），搬进 `HumanMessage` 的会是占位符本身，附件彻底消失。

## Changed

- **`base_nodes/nodes/output_checker.py` 的错误文案**：`ToolMessage` 落在 `messages[-1]` 时的 reason 由 `AI工具调用未被处理` 改为 `ToolMessage 不合理地出现在了 message[-1]`。原文案把「结构异常」表述成了「工具调用没被处理」，与实际成因不符 —— 正常流程下末条 `ToolMessage` 只可能来自结构被破坏。

## Removed

- **`utils/guards.py` 的四个冗余守卫**：删除 `is_target_message`（把「是工具消息」与「有块内容」耦合成单一条件，正是本次缺陷的根因）、`is_tool_message`、`is_block_content`（内联为 `isinstance`）、`is_string_result` / `is_block_result`（定义并导出但从未被调用）。文件现只保留 `is_target_model`，`utils/__init__.py` 的导出同步收窄；顺带删除未使用的 `typing.Any` 导入。

## Note

- **为什么 `is_target_message` 必须删**：它返回 `is_tool_message(message) and is_block_content(message.content)`，把两个正交的判断合并。调用方写 `if not is_target_message(message)` 时，意图是「遇到边界消息就 flush」，但实际匹配到的是「遇到不带块列表的消息就 flush」——`ToolMessage(str)` 因此被当成边界。拆成独立判断后，每种形态各走各的分支，不再有语义重叠。
- **触发条件与图片无关**：由于 `is_block_content` 只判断 `isinstance(content, list)`，任何 MCP 工具返回的 `[{"type": "text", …}]` 都会被当成附件。因此「MCP 工具 + 本地工具」混用即可触发，不需要真的产生图片。
- **顺序敏感**：只有「块在前、`str` 在后」才炸。`str/list` 组合下 `pending` 在末尾才倒出，结构恰好合法 —— 这也是 0.18.0 上线后表现为「某些会话炸」的原因。
- **坏结构不自愈**：非法结构一旦落进 `checkpoint_blobs`，每轮都会重新读到，该会话从此每轮必崩，只能按 `thread_id` 清三表。本版只防新增，不修历史数据。
- **`is_block_result` 的签名陷阱**：中间版本曾写成 `def is_block_result(content: ToolMessage)` 但函数体按 `list` 处理，按注解传 `ToolMessage` 永远返回 `False`。该函数已随本次清理删除。

## 校验

- **组合枚举**（1~3 个工具、`list` / `str` 全排列，共 14 组）：**结构全部合法、原始内容全部完整**。修复前 5 组产出非法结构。
- **真实 API 对照**（`deepseek-official/deepseek-flash`）：合法结构 `AI(c1,c2) → TM → TM` 返回 `200`；坏结构 `AI(c1,c2) → TM → Human → TM` 返回 `400 insufficient tool messages following tool_calls message`。
- **落盘验证**（真实 `StateGraph` + `InMemorySaver`）：修复前坏结构确实写入 `channel_values`，修复后不再产生。
- **语法 / 导入 / 格式**：4 个改动文件 `py_compile` 全过、可正常导入、无未使用导入、无空格缩进、import 块内 tab 对齐（块内最长前缀后的下一个 4 的倍数）、文件均以换行结尾、顶层 `def` 前 2 个空行。
- **未验证**：NcatBot 运行时下的端到端对话仍未跑。
