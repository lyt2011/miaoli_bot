# v0.26.1 - 2026-10-21

> 🐞 **修复 `recognize_intent` 的优先级写反，意图提示词从未真正进入上下文**。注释写的是「必须早于 `prompt_builder`」，代码却给了 `NORMAL`（0），而 `build_prompt` 挂的是 `NORMAL + 1`（1）—— 数值大者先跑，于是拼装在先、写段在后，段写进去了但没人再读它。

`_dispatch` 在同一个事件内是**共用一份 `view`** 的：前一个处理器返回的更新会被合并进 `view` 再传给下一个。所以「谁先跑」直接决定「谁写的内容能被读到」。修复后的实际顺序：

```
priority=10     recall_mcp_tools
priority= 2     recognize_intent    ← 写 prompt 段
priority= 1     pick_tools
priority= 1     build_prompt        ← 消费 prompt 段
priority=-9999  on_before_request
```

取 `NORMAL + 2` 而不是 `NORMAL + 1`，是为了留出一档空隙：`NORMAL + 1` 与 `prompt_builder` 同值，排序只能靠注册先后决定，不稳定。
