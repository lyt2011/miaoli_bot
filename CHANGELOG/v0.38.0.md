# v0.38.0 - 重构中（未发布）

> 🧱 **消息入口从 `@registrar.on_message` 迁到通道**。主包不再自己接消息：缓冲与记录搬进独立插件 `miaoli_buffer`，主包只留一份「注册表 + 一轮内只读快照」，靠 `ChannelSurface.batch_drain()` 并发取空各通道。本版是重构中间态，唤醒入口 `wake()` 尚未接线，消息驱动的自动回复暂时不通。

## Added

- `core/notice_channel/`：`ChannelRegistry`（`register` / `unregister` 幂等，`to_surface()` 出一份快照）与 `ChannelSurface`（`batch_drain(atimeout)` 用 `asyncio.gather` 并发 `drain()`，单通道异常或超时只落在自己那一路，键是通道名）
- `protocols/base_channel.py`：`BaseChannel`（`name` / `drain()`）；`protocols/channel_message.py`：`ChannelMessage`（`to_text()`），两条抽象都从 `miaoli_bot.protocols` 导出
- `api/channel_ops.py`：`register_channel(channel) -> Callable[[], None]`，返回幂等注销函数
- `consts/share_store_keys.py`：新增 `MAIN_READY`（`asyncio.Event`）；`channel_ops.register_channel` 与 `main.py` 的 `on_startup` 末尾 `set()` 一起构成「子插件装完才算就绪」的口子
- 独立插件 `plugins/miaoli_buffer/`：`EventBuffer` / `QQChannel`（`name="qq"`）/ `QQChannelMessage`（`to_text()` 直接返回 `event._data.model_dump_json()`），`manifest.toml` 用 `[dependencies] miaoli_bot = ">=0.37.0"` 保证排在主包之后加载

## Changed

- `main.py` 的 `on_message` 整块删除，`prepare_plugins()` / `load_plugins()` 从 `on_load` 挪到 `@registrar.on_startup()`（监听已在 `_startup_core()` 里起好，此时装子插件不会漏事件）；`on_load` 仍建 `Loader` 供 `on_close` 使用
- 执行锁从「每个会话一把」改成全局单例：`INVOKE_LOCKS` → `INVOKE_LOCK`，`main.py` 的 `Dict[str, asyncio.Lock]` → `asyncio.Lock()`
- `api/lock_ops.py` → `api/sync_ops.py`，`wait_main_ok()` → `wait_main_ready()`，实现改为 `await SHARE_STORE.recall(MAIN_READY).wait()`
- `core/graph_pipeline/runtime/` → `core/graph_pipeline/runtimes/`
- `README.md` / `README/en.md`：目录树、`api/` 门面清单、`SHARE_STORE` 键、子插件数量改为 17、配置表与数据流按当前代码重写；顶部与「项目状态」标明本版处于重构中

## Removed

- `core/ob11_buffer/`（`EventBuffer`）与 `EVENT_BUFFER` 常量、`main.py` 的缓冲装配与 `record_anything`
- 子插件 `plugins/ob11_buffer/` 与其 `get_qq_unread_messages` 工具（缓冲改由独立插件 `miaoli_buffer` 提供，工具暂缺：没有固定消息 id，模型侧无法挑拣）
- 根配置的 `split` / `typing` / `buffer` 三段及 `ReplySplitConfig` / `TypingSpeedConfig` / `BufferConfig` 三个模型

## Fixed

- `ChannelSurface.batch_drain` 的四处手误：`self.self._channel` → `self._channels`、`return_exception` → `return_exceptions`、`zip(self._channels.values(), …)` 把 channel 对象当键 → `zip(self._channels, …)`、文件头 `from asyncio import gather` 与正文 `asyncio.gather` 不一致
- `core/notice_channel/` 缺 `__init__.py`，`channel_registry` / `channel_surface` / `channel_message` 三处缺导入，`core/__init__.py` 仍指向旧路径 `core.channel_registry`

## Note

- **未发布**：`wake()` 入口、发送侧（`final_answer` 取用 / 切块 / 发送）与 `pick_tools` 的身份来源都还没接上。`pick_tools` 仍读 `state["event"]["sender"]["user_id"]`，入口改造后该字段不存在，现在调用必 `KeyError`
- `config.example.yaml` 仍留着 `split` / `typing` 两段：`PluginConfig` 是 `extra="allow"`，多出来的键被忽略，不会报错
- `QQChannelMessage.to_text()` 返回 `model_dump_json()` 的输出，其中 `message_id` / `user_id` / `self_id` 是字符串（pydantic 序列化结果），与 `model_dump()` 里的整数不同
