# v0.49.2 - 2026-11-13

> 🔧 **工具通道改写成「正文自动送达」的事实加判断句**，替掉 0.49.1 那串禁令。禁令在长上下文里竞争不过工具的描述，而送达机制是模型可以做规划的前提。

## Changed

- `output_protocol.md` 的 `### 工具通道` 重写：开头写明最终回复正文会自动发给当前对话目标，接着给出调用前的判断句「正文能否完成这次需求」，能就只写正文；四类工具用途由 bullet 列表压成一句；末尾保留「工具消息整段发送、不按空行分条」与「工具已发出的文字正文不再重复」。
- 同一节的字数由 179 汉字降到 142 汉字，协议整体 770 → 654 字符（562 → 468 汉字）。

## Removed

- `## 通用机制` 的第一条（「普通文字直接写在回复正文里，系统会自动送达，不需要调用发送工具；调用工具会让同一条内容发送两遍」）。新小节已覆盖送达、走正文、不重复三件事，两处并存是重复；原句把调工具写成必然导致重复，容易让模型把调用工具整体当成错误行为。

## Note

- 触发这次改写的现场在 `group-1046279455`：模型收到一个 @ 之后，同一轮调了 `send_meme_to_qq` 与 `send_message_to_qq`，把「就戳我一下然后什么都不说？\n有事说事喵」用工具整段发出（单换行、不分条），随后又在正文写了同一句（双换行、被切成两条），对方收到的是表情包加同一条话的两份。
- 分条机制本身没有坏，正文那条被正确切成两条；出问题的是走工具的那条路径。
- 最薄的一环是「发表情包顺带说一句」这种组合：判断句会判成正文不能完成，模型去调工具，之后能否忍住不在正文里重复，全靠末句。这条要专门实测。
- 提示词文件每轮读取，改完不需要重启服务。
