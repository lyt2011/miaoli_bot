# v0.21.0 - 2026-10-19

> 🧱 **`qq_adapter` 更名 `ob11_adapter`、根配置改回 `List[Provider]` + `List[LLM]`、新增 `miaoli_bot_adapter` 子插件**。三件事都围绕「名字与结构要说出真实含义」：旧名 `qq_adapter` 容易让人以为它「接入 QQ」，实际它只解析主包已经带进来的 OB11 事件字典；`providers` / `models` 曾经为了解析方便改成字典，那是错的，现在改回列表、名字由 `name` 字段承担。**破坏性**：自定义子插件若引用 `qq_adapter` 的 `SHARE_STORE` 键命名空间、或按字典方式读根配置的 `providers`，都会失效。

## Added

- **`plugins/miaoli_bot_adapter/` 子插件** —— 与 `ob11_adapter` 对称：后者适配**信息**（ncatbot 的 OB11 事件），前者适配**主包内部数据**（根配置）。
  - `inject_model_info` 挂在 `on_turn_start`（`priority=NORMAL+1`），调 `miaoli_bot.api` 的 `get_provider_info()` / `get_model_info()`，把 `base_url` / `api_key` / `model` / `max_tokens` 四个值写进 `state`。
  - `build_client` 因此不再读根配置、只消费 `state`，图节点与「`providers` 是列表还是字典」彻底解耦。
  - `enable: false` 时只写 `SHARE_STORE`、不注册节点。
- **`api/sugar.py` 新增 `get_provider_info()` 导出**（此前只有定义、未从 `api/__init__.py` 导出）。
- **`api/store_ops.py` 的 `store_contains` 导出**（`api/__init__.py` 的导入与 `__all__` 同步补齐）。

## Changed

- **`plugins/qq_adapter/` → `plugins/ob11_adapter/`**（`git mv`，35 个文件，历史保留）：
  - 入口类 `QQAdapterPlugin` → `OB11AdapterPlugin`，`plugin.toml` 的 `enter_class` 同步。
  - `SHARE_STORE` 键命名空间 `miaoli_bot/subplugin/qq_adapter.*` → `miaoli_bot/subplugin/ob11_adapter.*`（`PLUGIN_CONFIG` / `RAW_CONFIG` / `EVENT_PARSER` / `SEGMENT_PARSER` / `REGISTRY` 五个）。
  - 类与注册器 docstring 由「qq 平台适配」改为「OB11 事件适配」。
- **根配置 `providers` 改回 `List[Provider]`、`models` 改回 `List[LLM]`**：
  - `Provider` 新增 `name` 字段，`models` 由 `Dict[str, LLM]` 改为 `List[LLM]`；`LLM` 新增 `name` 字段。
  - `provider` / `model` 两个选择字段保留，由 `PluginConfig` 的 `model_validator` 校验它们确实存在于 `providers` 里。
  - `config.example.yaml` 与 `config.yaml` 同步改成列表写法。
- **`build_client` 改为纯消费 `state`**：删掉 `root_config = store_recall(PLUGIN_CONFIG)` 这个已无引用的死变量，以及随之失效的 `store_recall` / `PLUGIN_CONFIG` / `Dict, Any` 导入；返回注解由 `Dict[str, Any]` 改为 `None`（该节点只写 `runtime.context`，不返回 state 增量）。
- **`web_search` 子插件重写**（用户改造 + 本轮修复）：
  - `provider` → `adapter`，取值由 `Literal["langsearch"]` 扩为 `Literal["langsearch", "deepseek"]`。
  - `base_url` → `api_url`（语义更清晰：这里是插件自己 `post` 的完整路径，与根配置 `providers.base_url` 只填到 `/v1` 不是一回事）。
  - 密钥由「从环境变量读」改为配置里直接必填 `api_key`（`env_key` / `PrivateAttr` / `model_validator` 一并删除）。
  - `on_load` 由 `if` 链改为 `TOOL_MAPPING[config.adapter]`；新增 `deepseek_search` 工具。
  - **两个后端共用工具名 `web_search`** —— `adapter` 只影响工具入参 schema 与返回数据形状，不影响工具名。
  - `README.md` 重写（旧版描述的是 `provider` / `env_key` / `success()` 时代的实现，与代码已多处不符）。

## Removed

- **`plugins/ob11_adapter/models/config/split.py` 与 `SplitConfig`**：全仓零消费点 —— 实际读的是根配置的 `split` / `typing`，且字段名都不同（`split_separator` vs `delimiter`、`base_typing_speed` vs `base_speed`），是 0.17.0 重构前的遗留。`PluginConfig.split` 字段、两处 `__init__.py` 的导出、`config.example.yaml` 的 `split:` 段同步删除；该插件的 `config.yaml` 只剩 `enable: true`。
- **`models/config/provider.py` 的 `Dict` 导入**（改回列表后已无引用）。

## Fixed

- **`models/config/provider.py:27` 的 `List[LlM]`**（小写 `l`）→ `List[LLM]`。实测实例化 `Provider` 直接 `PydanticUserError: Provider is not fully defined; you should define LlM`。
- **`models/config/plugin.py` 缺 `List` / `LLM` 导入** → 实测 `PydanticUserError: PluginConfig is not fully defined`，配置校验无法进行。
- **`models/graph_state.py:10` 的 `add_message`**（少个 `s`）→ 恢复为 `Annotated[str, UntrackedValue]`。原写法让 `GraphPipeline()` 构造时直接 `NameError`，是当时 12 个子插件加载失败的共同根因。
- **`api/sugar.py` 的 `get_provider_info()` 三处错**：`provider_name` 未定义（`NameError`）、`return KeyError(...)` 而非 `raise`（返回异常对象，下游 `["base_url"]` 会炸 `TypeError`）、`providers[plugin_cfg.providers]`（把 `list` 当字典键）。`get_model_info()` 里两个 `return KeyError` 一并改为 `raise`，错误消息补上实际的供应商 / 模型名。
- **`plugins/base_nodes/nodes/build_client.py:22` 的 `model_name`**（未定义）→ `model`。
- **`web_search/tools/deepseek_search.py` 完全没有导入**：第 1 行直接就是 `class ToolSchema(BaseModel)`，补 `store_recall` / `tool` / `BaseModel, Field, model_validator` / `Any, Dict, Optional, Self` / `..consts` 五组导入。
- **`web_search/tools/__init__.py` 只导出 `lang_search`** → 补 `deepseek_search`；`main.py` 的 `TOOL_MAPPING` 用了它却没导入（模块加载即 `NameError`）。
- **`@tool(name="web_search", ...)` 会 `TypeError`**：`langchain_core.tools.tool` 的 `name_or_callable` 是**位置参数**，没有 `name` 关键字。两个工具改为 `@tool("web_search", args_schema=...)`，工具名仍是 `web_search`。
- **`deepseek_search` 的 `ori_question` 空值校验**：字段默认 `None`，原写法 `if not self.ori_question.strip()` 在省略该参数时 `AttributeError`，导致**任何不传 `ori_question` 的调用都崩**。改为 `if self.ori_question is not None and not self.ori_question.strip()`。
- **`web_search/config.example.yaml` 键名与 `PluginConfig` 不符**：`provider` / `env_key` 两个多余键、缺必填 `adapter` / `api_key`，照模板复制会 `ValidationError`。
- **`api/store_ops.py` 末尾缺换行**。

## Note

- **改名不是合并**：曾讨论把 `qq_adapter` 并入 `miaoli_bot_adapter`，最终只改名。理由是 adapter 的价值由「它隔离哪个变化源」决定，不由「输出去哪」决定 —— `ob11_adapter` 隔离的是**外部平台**（ncatbot / OB11 改版），`miaoli_bot_adapter` 隔离的是**自身根配置**结构。合并会让 63 行的插件吞掉 552 行的，且把 `on_agent_start`（`HIGH`）与 `on_turn_start`（`NORMAL+1`）两种时机绑进同一个 `on_load`，启用/禁用无法独立控制。
- **`models/graph_state.py` 的 `system_prompt` 保持 `Annotated[str, UntrackedValue]`**：它同时被 `account_injector` 写入、被 `call_llm` 当字符串读取。改成带 reducer 的 `list` 虽然能解决多节点覆盖问题（见 issue #2），但会连带改 `call_llm` 的取用方式，超出本版范围。
- **`README.md` 顺带修正了三处已失效的配置表行**：`prompt_file` 的 `FilePath` 校验（实际是 `Optional[str]` + 懒加载）、`system_prompt` 行（`PluginConfig` 没有这个字段）、`output` / `OutputConfig` 行（早已拆成 `split` / `typing`）。
- **`README.md:261` 的 v0.17.0 历史记录保留 `qq_adapter` 原文**（含当时的节点名 `handle_event`，0.17.4 才改名 `event_adapter`）—— 那是当时的事实，不随本次改名回溯修改。
- **`protocol` 字段仍是死字段**：`Provider.protocol` 有定义、零消费点，`build_client` 建 `ChatOpenAI` 时没有传 `use_responses_api`。实测 `langchain-openai 1.6.6` 默认按模型名推断（`gpt-5-pro` / `codex` 系走 `/responses`，其余走 `/chat/completions`），`deepseek-flash` 稳定走 chat/completions，所以当前配置下无实际影响。是否消费该字段待定。
- **`base_url` 语义已实测确认**：任意前缀都行（`/v1`、`/api`、`/openai/v1`、不带前缀），尾斜杠自动处理，但**不能填完整端点** —— 填 `.../v1/chat/completions` 会请求 `/v1/chat/completions/chat/completions`。
- **`web_search` 的 `summary` 字段占返回体积 80%**：`deepseek` 实测 `count=10` 时 43,780 字符（≈12,500 token），`summary` 占 81%。用户决定暂不裁剪（当前没有获取网页的工具，正文摘要仍有用）。
