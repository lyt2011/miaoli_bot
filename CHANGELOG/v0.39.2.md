# v0.39.2 - 2026-11-08

> 🧱 **`store_set()` 增加 `overwrite` 开关，让「有意覆盖」和「撞键」在日志里分得开**。此前只要键已存在就无条件打一行 warning，需要按轮刷新状态的调用方每轮都会踩一次，告警被稀释成背景噪音。

`store_set()` 原来那条告警是给「两个子插件用了同一个键」这类事故准备的：`on_load` 里写配置键，正常路径下这个键不该已经存在，出现了就说明有残留或者撞键。但同一个函数也承担着「刷新状态」的职责 —— 调用方明知键在，仍要把它换成新值。这两种意图以前在代码里长得一模一样，日志只能把两件事都说成「被重复设置」。

现在由调用点自己声明意图：不传 `overwrite` 就维持原行为（键已存在时打 warning），传 `overwrite=True` 表示「我知道我在覆盖」，不打。参数是 keyword-only，`store_set(k, v, True)` 这种从调用点读不出意思的写法不会通过。

## Added

- `api/store_ops.py`：`store_set(key, value, *, overwrite: bool = False)` 新增 keyword-only 参数 `overwrite`。

## Changed

- `api/store_ops.py`：重复设置的告警条件从「键已存在」改成「键已存在且没传 `overwrite`」。返回值仍是 disposer，其它行为不变。

## Note

- `overwrite=True` 只影响那行 warning：disposer 照样返回，`undo()` 照样只在「容器里现在还是我写进去的那个对象」时才 `drop`。所以按轮覆盖的键，早先拿到的旧 disposer 不会误删后来者写入的新值。
- 覆盖时完全静默。以后要查「这个键的值为什么变了」，得自己在那条路径上加日志。
