# v0.27.2 - 2026-10-21

> 🧱 **意图注入段前面加一行统一引导语**。说明这段内容是每轮重建的、不会保留，有用就去读原文件、持久化进上下文。

`prompt` 段是每轮按匹配规则重建的：下一轮规则不命中，段就消失。而磁盘上的文件一直在，读回来的 ToolMessage 落在 `messages` 里会持久保留。所以引导语要说的不是「这是什么」，而是「这一段留不住、有用就得自己去读」。

## Added

- `plugins/intent_recognition/nodes/recognize_intent.py`：新增 `GUIDE` 常量。

  ```
  以下本轮的意图识别注入内容，不会保留；有用就读原文件持久化进上下文。
  ```

## Changed

- `recognize_intent` 返回的 `intent_recognition` 段由「`build_prompt(field_prompts)`」变为「`GUIDE` + 换行 + `build_prompt(field_prompts)`」。

## Note

- `GUIDE` 不点名具体工具。早先一版把 `read_file` 写死在里面，用工具名的硬编码换「有力」；工具一旦改名、挪子插件或部署里没装，这行字就成了指向不存在工具的死指令。
- **当前版本关掉 `with_path` 会让模型自我怀疑然后一顿瞎试**：路径的唯一来源是 `with_path` 追加的 `(from /abs/path.md)` 后缀，关掉之后引导语仍要求「读原文件」，但模型手里没有任何可读路径 —— 它会先怀疑自己是不是漏看了什么，然后去猜路径、瞎调读取工具。不崩，但 `with_path: false` 与这行引导语在语义上是互斥的。
