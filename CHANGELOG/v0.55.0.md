# v0.55.0 - 2026-11-15

> 🧱 **图的进出口收成两个 state 字段**。`main.py` 不再自己拼 `HumanMessage` 送进图、也不再从 `messages` 末条里猜回复，改为只写 `state["input"]`、只读 `state["output"]`；两侧的搬运交给 `miaoli_bot_adapter` 的两个新节点。`input` / `output` 用 `UntrackedValue` 通道承载，不进 checkpoint。

## Added

- `models/graph_state.py`：`GraphState` 增加 `input` 与 `output`，类型都是 `Union[str, List[dict]]`，通道是 langgraph 内置的 `UntrackedValue`。
- `plugins/miaoli_bot_adapter/nodes/input_to_messages.py`：`input_to_messages` 把 `state["input"]` 包成一条 `HumanMessage` 追加进 `messages`；`input` 缺失或为空时返回 `None`，不写增量。
- `plugins/miaoli_bot_adapter/nodes/messages_to_output.py`：`messages_to_output` 把 `messages[-1].content` 写进 `state["output"]`；末条不是 `AIMessage`、或带 `tool_calls` / `invalid_tool_calls` 时返回 `Abort`。
- `plugins/miaoli_bot_adapter/main.py`：注册 `input_to_messages`（`ON_AGENT_START`，`MEDIUM`）与 `messages_to_output`（`ON_AGENT_END`，`TRIVIAL`）。

## Changed

- `main.py`：`_run_channel_graph` 传给 `safe_run_graph` 的 state 从 `{"messages": [HumanMessage(content, ...)]}` 改成 `{"input": content}`，不再在主包里构造 `HumanMessage`。
- `main.py`：回发分支从 `case {"messages": [*_, last]} if isinstance(last, AIMessage)` 改成 `case {"output": out}`，直接读 `state["output"]`，不做类型校验。
- `models/graph_state.py`：字段按归属分成两组并加注释——`messages` / `prompts` 服务于 langgraph，`input` / `output` 是可替换的进出口。

## Removed

- `main.py` 不再往 `HumanMessage.additional_kwargs` 里写 `platform`，整行 `from langchain_core.messages import HumanMessage, AIMessage` 随之删除。

## Note

- **`platform` 现在拿不到了。** 旧行为是 `main.py` 构造 `HumanMessage` 时挂 `additional_kwargs={"platform": message.platform}`，同一个值还能从 `BaseChannelMessage.platform` 读到。现在那条 `HumanMessage` 由 `input_to_messages` 在 `ON_AGENT_START` 里造，`GraphState` 也没有承载它的字段——所以**图内任何节点或工具都无法得知这一轮的来源平台**。`platform` 只活在 `channel.reply(message.platform, ...)` 与通道消息对象上，属于图外。跨渠道共用一个 `thread_id` 时，图内暂时无法区分来源。补它需要先决定放 `GraphState` 新字段还是 `GraphRuntimeContext`，本次未做。
- **`recognize_intent` 没有跟着改。** 它仍在 `ON_TURN_START` 读 `messages[-1]`，并在 `isinstance(..., (AIMessage, HumanMessage))` 成立时把正文当本轮用户输入。`input_to_messages` 在 `ON_AGENT_START` 就造好消息，所以它的行为与改动前一致；但这层依赖是跨插件的隐式约定，没有类型约束。
- `messages_to_output` 的优先级取 `TRIVIAL`（`-1000`）：低于 `output_checker`（`LOWEST`，`-100`）以便借它确认末条是 `AIMessage`，又高于 `default_routing` 的 `on_agent_end`（`MINIMUM`，`-9999`）——后者返回 `Goto(END)`，同优先级时会短路其后所有处理器。`MINIMUM + 1` 也能达到同样效果，用常量更直观。
- `input` / `output` 不落 checkpoint，因此**每轮调用方都必须重新给 `input`**，不能指望从 checkpoint 恢复。
