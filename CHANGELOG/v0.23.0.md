# v0.23.0 - 2026-10-20

> 🧱 **`context_compactor` 配置分层 + 修复二次压缩守卫从未生效**。守卫的判据位置从一开始就是错的，而压缩本身也因一个未定义变量从未成功执行过。

两件事撞在一起：**配置要能表达「压缩行为」这一组参数**，以及**排查配置结构时发现守卫根本没在工作**。

**配置分层**：`PluginConfig` 此前把 `enable` 和压缩参数平铺在同一层（`keep_count` / `encoding` / `prompt_file` / `recall_system_prompt` / `calculate`），读配置时看不出哪些字段属于「压缩行为」。拆出 `CompactConfig` 收纳压缩参数与提示词懒加载，`PluginConfig` 只留 `enable` / `calculate` / `compact`，与 `calculate` 的分层方式对齐。

**守卫的三处错误**，逐层挖出来的：

1. **`compact` 节点的 `message[0]` 是未定义变量**（应为 `messages[0]`，0.22.0 引入）。`NameError` 被 `GraphPipeline._dispatch` 的 `except Exception` 吞掉、打一条 `LOGGER.exception` 后 `continue`，节点什么都没返回，`messages` 从未被覆盖。压缩请求照常发出、token 照常消耗，但上下文一个字没变 —— **压缩从未真正成功过**。更糟的是它不报错：`should_compact` 下一轮算出的 token 依然超限，于是 `guard → compact(崩) → on_after_compact → on_turn_start → guard` 反复循环。本地按 HEAD 逻辑复现，`compact` 被调用 **2502 次**后抛 `GraphRecursionError: Recursion limit of 10007`。
2. **守卫看的是 `messages[-1]`**（0.22.0 引入）。摘要被放在 `compacted_ctx[0]`，而 `keep_recent_messages` 保留的是**尾部**消息，所以 `messages[-1]` 永远是某条保留消息，摘要根本不在那个位置。这个判据从写下那天起就没有命中过一次 —— 0.22.1 里「补齐 `Abort` 导入后拦截恢复」的结论是错的，补上导入只是让它从 `NameError` 变成「判据不成立」，两者都不拦截。
3. **判据靠字符串硬编码在两处**。`compact` 写 `<compaction>`、`should_compact` 找 `compaction`，改标签名时漏改一边就是静默失效。改标签为 `<abstract>` 的同时把常量收进 `consts/tags.py`。

修法：`compact` 改用 `messages[0]`；守卫先过滤掉 `SystemMessage` 再检查首条 —— 因为 `recall_system_prompt` 决定摘要前面有没有提示词，摘要位置在 `[0]` / `[1]` 之间浮动，按类型过滤比猜下标可靠。

**压缩提示词换版**：经四轮消融实验（旧版 / +工具禁令 / clop5.5 版 / gpt-6-sol 版，各 2~3 轮 × 4 窗口 × 带不带人设），最终形态取 clop5.5 的骨架 + gpt-6-sol 的三条补充（只依据输入、不要合并实体、不确定时标注），并**删掉 gpt 版里那条「在长度受限时先删去寒暄」** —— 模型无法判断长度是否受限，只读到「删」，实测把实体覆盖率从 69.3% 拉到 80.7% 就靠删这一句。

## Changed

- `models/compact_config.py`（新增）：`CompactConfig` 收 `recall_system_prompt` / `keep_count` / `encoding` / `prompt_file`，提示词改为 `PrivateAttr` + `prompt` 懒加载 property。
- `models/plugin_config.py`：`PluginConfig` 收窄为 `enable` / `calculate` / `compact`（破坏性 —— 旧的扁平写法不再被识别）。
- `consts/tags.py`（新增）：`ABSTRACT_TAG = "abstract"`，`consts/__init__.py` 导出。
- `nodes/compact.py`：属性访问改 `plugin_cfg.compact.*`；摘要标签改 `<abstract>`；压缩结果先按类型过滤掉 `SystemMessage`，再由 `recall_system_prompt` 决定是否把原提示词插回首位。
- `data/compact_prompt.md`：换成实验最优版（clop5.5 骨架 + sol 三条补充）。
- `config.example.yaml`：按新结构重排，补 `recall_system_prompt`。

## Fixed

- `nodes/compact.py`：`message[0]` → `messages[0]`，修掉压缩节点必抛的 `NameError`。此前该异常被 `_dispatch` 吞掉，压缩静默失效且会陷入无限循环。
- `nodes/should_compact.py`：守卫判据从 `messages[-1]` 改为「过滤 `SystemMessage` 后的首条」。摘要位于头部而非尾部，原判据从未命中。
- `nodes/should_compact.py`：补 `Abort` 导入已在 0.22.1 完成，但当时未发现判据位置也错，本版一并修正。

## Note

- 线上未暴露这两个 bug，是因为会话 token 从未触及压缩阈值 —— 一旦触及就是 `GraphRecursionError` 死循环，而不是「压缩没效果」这种温和表现。
- 守卫判据现在依赖「摘要永远在过滤后列表的首位」。若将来有节点在压缩后往 `messages` 头部插入别的 `HumanMessage`，会误拦。之所以够用，是因为当前只有 `compact` 会重写 `messages`，且它总把摘要放第一位。
- 压缩请求仍带完整 `messages`（含 `SystemMessage`），即默认「带人设压缩」。实验显示新提示词下带与不带差 2.4pp（两轮样本，噪声内），故不为此新增开关。
