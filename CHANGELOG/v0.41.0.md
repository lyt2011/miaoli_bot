# v0.41.0 - 2026-11-08

> 🧱 **唤醒改成事件驱动，`llm.thinking` 改名 `thinking_effort`**。`main.py` 不再用 `Job(run_graph, Every(60s))` 轮询，改成一个常驻 `tick` 任务 `await` 在 `RUN_REQUESTED` 事件上 —— 任何子插件调 `api.please_run_graph()` 就能提前唤醒，兜底间隔只负责「没人叫」的情况；同时 `llm` 段的思考强度键改名为 `thinking_effort`，旧 `config.yaml` 会校验失败。

轮询的代价是可算的：60 秒固定间隔下的平均等待就是 30 秒，而实测端到端时延里「排队」占了 77%。事件驱动之后，消息进缓冲就能立刻叫醒主包。反过来也成立 —— 一次请求不保证一次执行（没数据直接跳过），一次执行也不对应一次请求（N 次 `set()` 合并成 1 次唤醒）。

`please_run` 这个名字是按四判据挑的：不传数据、不返结果、不阻塞、**不一定跑**。`request` / `trigger` / `schedule` 都隐含「会被兑现」，而它本质上只是个标记。

## Added

- `consts/share_store_keys.py`：新增 `RUN_REQUESTED`（`miaoli_bot/core.run_requested`），core 的容器键从 11 个变成 12 个。
- `api/sync_ops.py`：新增 `please_run_graph()` —— 置位 `RUN_REQUESTED`，没有参数、没有返回值、不阻塞；连着调 N 次只对应一轮跑图。
- `models/config/tick_config.py`：新增 `TickConfig`（`interval: float`，默认 `60.0`，`gt=0`），`PluginConfig` 多出 `tick` 段。
- `config.example.yaml`：新增 `tick:` 段。

## Changed

- `main.py`：唤醒从 `Job(self.run_graph, Every(timedelta(seconds=60)))` 换成 `tick(tick_interval)` 协程 —— 每轮 `await_for(RUN_REQUESTED.wait(), timeout=tick_interval)`（`TimeoutError` 就是兜底到点），醒来先 `clear()` 再 `run_graph()`。`clear()` 必须在跑图**之前**：放在后面的话，跑图期间到达的请求会被一起抹掉，那批消息只能等下一次兜底超时。
- `main.py`：`plugin_loader` 的实例化、`prepare_plugins()` / `load_plugins()`、`tick` 任务的创建全部从 `on_load` 挪到 `on_startup`（`on_load` 只造容器数据），`MAIN_READY.set()` 落在最后一行。
- `main.py`：`tick` 任务带一个 `add_done_callback` —— 任务意外结束时打日志并重新创建，但只在 `MAIN_READY` 置位时重启；`on_close` 开头先 `clear()` 它，于是关闭期间的正常结束保持静默。
- `main.py`：`on_close` 的顺序改成「`clear(MAIN_READY)` → `cancel` + `await tick` → `unload_plugins()` → `cpa.close()` → drop 各键」。原顺序先卸插件，而循环此时可能正拿着这些插件注册的工具跑图。
- `main.py`：`run_graph` 不再 `await MAIN_READY.wait()`，改成一行 `assert`（调用时序由 `on_startup` 保证）。
- `main.py`：不再从 `core` 导入 `Every` / `Job`，`self.auto_waker: Job` 换成 `self.tick_task: asyncio.Task`。
- `models/config/llm_config.py`：`thinking` 改名为 `thinking_effort`（破坏性）—— `PluginConfig` 要求新键，旧 `config.yaml` 直接 `ValidationError`。
- `api/__init__.py`：`safe_run_graph` 改成从 `core` 直接转出，`please_run_graph` 加进 `sync_ops` 的导出；`__all__` 仍是 16 项（去掉 `get_pipeline`、加上 `please_run_graph`）。

## Removed

- `api/pipeline_ops.py`：整个文件删除，`get_pipeline()` 随之消失（破坏性）。它返回裸 `GraphPipeline`，调用方拿到后自己 `ainvoke` 会绕过 `graph_runner` 里的 `INVOKE_LOCK` —— 两个 `ainvoke` 同时写同一个 `thread_id` 的 checkpoint，轻则丢历史、重则让 checkpointer 抛错。要跑图只剩两条路：`safe_run_graph()`（带数据、同步拿结果）与 `please_run_graph()`（不带数据、不拿结果、可能被跳过）。

## Fixed

- `utils/sugar.py`：`easier_send` 的分支从 `if / else` 改成 `if / elif / else`，非法的 `mode` 不再静默当成私聊发送，改为抛 `ValueError`。

## Note

- **旧 `config.yaml` 会校验失败**：`llm.thinking` 必须改成 `llm.thinking_effort`。
- `core/scheduler/`（`Job` / `Once` / `Every`）仍在仓库里，但已经没有使用者 —— 唤醒改由 `main.py` 的 `tick` 任务负责。
- 重启回调只在任务**整轮退出**时触发。`tick` 内部没有兜住 `run_graph` 的异常，所以一次跑图失败会让整轮任务结束并重启：后续轮次不受影响，但这一轮已经 drain 出来的消息不会重放。
- `tick.interval` 必须大于 0：0 会让 `wait_for` 立刻超时，退化成忙循环。
