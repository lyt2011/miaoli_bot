# v0.53.0 - 2026-11-14

> 🧱 **把「能力」从主包里挖出去，主包只留机制与契约**。上下文压缩与模型调用重试各自独立成库型子插件 `base_compact` / `base_llm`；QQ 专属的 `easier_send` 与 `meme_ops` 一起迁去 `miaoli_qq_channel`。主包此后不认识 QQ，也不持有任何提示词资产。

## Added

- `plugins/base_compact/`：上下文压缩能力，从 `core/compact/` 整体迁入（19 个文件）。按 `api` / `core` / `runtimes` / `utils` / `consts` 分类，无节点、不注册事件，只对外提供能力。`api/` 把四层的 19 个公有符号全部转出 —— `compact_now` / `ChatHistory` / `CompactSuccess` / `CompactFailed` / 7 个纯函数 / 8 个常量与模板。
- `plugins/base_llm/`：带重试的模型调用入口，从 `core/llm/` 与 `errors/max_retry_limit_error.py` 迁入。`call_llm(messages, client, *, max_retry=0)` 返回 `(尝试次数, 途中全部异常, 最终回复)`，放弃时抛 `MaxRetryLimitError`（继承主包 `BaseBotError`，带 `exceptions` 与 `times`）。
- `plugins/base_nodes/metadata.toml`：新增 `[[dependences]] name = "base_compact"`，加载次序由拓扑排序保证，不靠目录名。
- 两个新插件各带 `README.md`；`base_compact` 的压缩提示词 `COMPACT_PROMPT` 随之搬出主包。

## Changed

- `plugins/base_nodes/nodes/compact.py`：`compact_if_need` 取摘要的来源从 `core.compact` 改为 `base_compact.api`（同一个函数对象，行为不变）。
- `miaoli_bot/plugins/` 的内置子插件从 13 个变成 14 个（加 `base_compact` / `base_llm`，减 `meme_ops`）。
- 全仓模块顶部导入按统一规则重排并做列对齐：26 个文件重排、34 个文件产生 diff，导入集合与顶层定义逐文件比对无变化。
- 两个新插件的 `__all__` 统一成「按来源模块分组 + 组间与组内升序」的格式；`api/` 不再挑选，各层公有符号全量转出（`LOGGER` 除外，与主包 5 处模块级日志器的惯例一致）。

## Removed

- `core/compact/`（19 个文件）与 `core/llm/`（4 个文件）：代码本身没变，只是换了宿主。
- `errors/max_retry_limit_error.py`：随 `base_llm` 迁走，改由该子插件定义。
- `utils/sugar.py`：`easier_send` 迁去 `miaoli_qq_channel/utils/easier_send.py`（唯一改动是不再直接 `SHARE_STORE.recall(NCATBOT_API)`，改走 `miaoli_bot.api.get_ncatbot_api()`）；`concatenate_id` 只有测试在调，随之删除。
- `tests/test_sugar.py`：被测对象已不存在。
- `plugins/meme_ops/`（22 个文件）：整体迁去 `miaoli_qq_channel/plugins/meme_ops`，`tools/send_meme.py` 的 `easier_send` 改从通道取。
- `api/__init__.py` 的 `easier_send`、`utils/__init__.py` 的 `concatenate_id`、`core/__init__.py` 的 11 个压缩符号与 `call_llm`、`errors/__init__.py` 的 `MaxRetryLimitError`。

## Note

- **破坏性**：`from miaoli_bot.core import compact_now / call_llm`、`miaoli_bot.errors.MaxRetryLimitError`、`miaoli_bot.utils.easier_send`、`miaoli_bot.api.easier_send`、`miaoli_bot.utils.concatenate_id` 全部失效；`miaoli_bot.api.__all__` 从 16 项降到 15 项。改法：压缩与重试改从 `base_compact.api` / `base_llm.api` 取，发送改从 `miaoli_qq_channel.utils` 取。
- **`base_llm` 仍然是零调用点**：`base_nodes` 的 `call_llm` 节点与 `base_compact` 都还是直接 `client.ainvoke`，`is_retriable` 恒 `False`，所以既不会重试、也没有 `max_retry` 配置可调。接线要排除 `400` 类，只对超时 / 限流 / `5xx` 重试。
- **`intent_recognition` 的 `file` 指向 `/home/miaoli_bot_info.md`**，本机不存在，该插件在 `model_validate` 阶段就因 `FilePath` 校验失败而加载不起来 —— `enable: false` 挡不住这一步。要恢复得放一个真实文件，或把它指到已有路径。
- 根目录的 `data/` 已随提示词资产一起移除，`.gitignore` 里那条 `data/intent_prompts/` 保留（无害，重新建目录时仍生效）。
- `meme_ops` 迁去另一个仓库后，`sub_plugin.load_from` 需同时列出两个仓库的 `plugins/` 目录才能照旧加载；它自己的 `config.yaml`（含 sqlite 路径与 `help_doc.path`）不在任何仓库里，迁移时要跟着改绝对路径。

## Docs

- `README.md` / `README/en.md`：目录树删掉 `core/compact/` `core/llm/` `data/` `utils/sugar.py`，加入 `base_compact/` `base_llm/`；内置子插件计数与 `api/__all__` 计数同步；子插件表删 `meme_ops` 行并注明去向；`easier_send` 的出处由 `miaoli_bot.api` 改为 `miaoli_qq_channel.utils`；`aiosqlite` 的用途去掉 `meme_ops.MemeSqlite`。
- `plugins/base_compact/README.md`：目录表把 `api/` 一行改为「四层 19 个公有符号全量转出」。
