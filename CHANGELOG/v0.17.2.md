# v0.17.2 - 2026-10-16

> 🔒 **并发冲突的最简修复：`on_message` 按 `session_id` 加 `asyncio.Lock`** —— 仅保证同一会话的**顺序**，后续会改进。

### Added

- **`main.py` 的 `MiaoLiBot.session_locks`**（`defaultdict(asyncio.Lock)`）：`on_message` 在「跑图 + 发送」整段外面 `async with self.session_locks[session_id]`，把同一会话的多个回合串成 FIFO 队列，避免同一 `thread_id` 上并发写 checkpoint

### Note

- **为什么用锁**：`asyncio.Lock` 本身就是 FIFO 队列，等待者按到达顺序唤醒 —— 同一会话的多条消息**按序处理、不丢**；「插话」的连续感由 checkpointer 提供（后一条消息的 run 会看到前一条留下的历史），**不需要**往运行中的图里注入（langgraph 也没有干净 API 这么做）。
- **仅保证顺序**：这是解决并发冲突的**最简实现**，只把同一会话的回合串行化；**不做**消息合并 / 优先级 / 超时取消 / 锁字典回收 —— 后续会改进。
- **发送也在锁内**：整轮（跑图 + 打字延迟的分块发送）当作一个不可分割的回合，代价是后一条消息要等前一条发完。
