# v0.22.3 - 2026-10-20

> 🧱 **`meme_ops` 注入表情包使用提示**。工具在工具表里不等于模型会用 —— 缺一步「先查表」。

`send_meme_to_qq` 需要一个 `hash`，模型手里没有，得先 `list_memes` 才知道库有什么。这一步是额外的工具循环，不提示的话模型不会为了一个表情包主动多跑一轮。实测 6 条情绪化输入（累、满分、被骂、晚安、大笑、难过），基线 0 条发图，连 `list_memes` 都不调。

## Added

- `meme_ops` 新增 `nodes/inject_helper.py`：`inject_helper` 节点挂在 `on_agent_start`（`priority=NORMAL`），把硬编码的 `MEME_HELPER` 常量写进 `prompt` 的 `meme_helper` 段，由 `prompt_builder` 在 `on_before_request` 拼装时带上。
- 提示词内容：先调 `list_memes` 看有什么表情包适合当前情景，若有契合的则用 `send_meme_to_qq` 发出去，并说明这是被鼓励的做法。

## Note

- 提示词硬编码在节点文件里，不进配置 —— 它描述的是工具本身怎么用，随工具一起变，没有部署期差异。
- 实测同样 6 条输入，加提示后 6/6 发图，且选中表情包全部与情景契合（累 → 摆烂、满分 → 竖拇指、被骂 → 生气炸毛、晚安 → 抱被子、笑 → 捶地、难过 → 摸头）。
- 关键在于**先查表**：只给「你可以发表情包」的授权没有效果（此前测过 0/4），模型需要明确知道库里有货、且被要求先看。
- 提示词里的工具名用实际注册名 `list_memes` / `send_meme_to_qq`。写成近似名（`list_meme` / `send_meme`）时模型能靠工具表猜对，但一旦工具表里出现相近名字就会选错。
