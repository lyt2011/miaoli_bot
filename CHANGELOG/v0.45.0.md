# v0.45.0 - 2026-11-10

> 🕒 **时间注入独立成插件，而且刻意拆成两个通道**。`time_injector` 每 `interval` 秒往 `messages` 末尾追加一条 `<time-inject>` 时间快照，同时往 `prompts` 写一段「这个标签是注入时刻的快照、以最后一条为准」的说明。
>
> 分开的理由是缓存，不是洁癖：`prompts` 的每一段都会进 `messages[0]` 的 `SystemMessage`，也就是整段输入的**头部**。供应商按前缀匹配上下文缓存，头部一变，后面几万 token 全部作废、全量计费。时间值每秒都在变，进 `prompts` 等于每轮主动撞碎缓存；说明文本是常量，进去之后 `SystemMessage` 每轮逐字符相同，边际成本接近 0。所以时间走尾部、说明走头部。

## Added

- 新子插件 `time_injector`（`plugins/time_injector/`）：`helper_inject` 挂 `ON_AGENT_START`（`NORMAL`）把 `time-inject-helper` 段写进 `prompts`；`time_inject` 挂 `ON_BEFORE_REQUEST`（`NORMAL + 2`）按会话节流，往 `messages` 末尾追加一条包在 `<time-inject>` 里的 `HumanMessage`。
- `PluginConfig` 四个字段：`enable`（默认 `true`）、`interval`（默认 `60.0`）、`template`（`Optional[Path]`，留空用内置模板）、`encoding`（默认 `utf-8`）。
- `utils/prompt_builder.py` 的 `build_time_prompt()`：用 `string.Template` 替换 `$now` / `$weekday`，时间格式 `%Y-%m-%d %H:%M:%S %z`，星期取 `weekday() + 1`（1–7）。
- `consts/prompt.py`：`DEFAULT_TEMPLATE` / `TAG` / `HELPER_TAG` / `HELPER_TEXT`；`consts/store_keys.py`：`PLUGIN_CONFIG` / `LAST_INJECTED_AT`。
- `config.example.yaml` 与 `README.md`。

## Note

- `config.yaml` 是这个插件的**必需项**：`on_load` 无条件执行 `PluginConfig.model_validate(self.config)`，缺文件时 `self.config` 为 `None`，直接 `ValidationError` 判加载失败。
- `LAST_INJECTED_AT` 只存在内存里（`Dict[thread_id, datetime]`），重启清空，所以每个会话重启后的第一条必定注入。
- `time_inject` 的 `NORMAL + 2` 是刻意的：要排在 `prompt_builder`（`NORMAL + 1`）之前，这样同一轮的 `build_prompt` 就能读到本轮刚写进去的说明段。
- `template` 只做类型校验，**不校验文件是否存在** —— 路径写错不会报错，`time_inject` 里 `path.is_file()` 为假就静默回落到内置模板。
- 时间块会在历史里累积 —— 每次注入都是一条独立 `HumanMessage`，旧块的时间戳会与新块并存。说明段用「以最后一条为准」缓解，`interval` 是最直接的抑制手段。
