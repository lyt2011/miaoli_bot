# v0.18.0 - 2026-10-17

> 📦 **子插件配置外置 + 权限表精简 + 两处插件改名** —— 11 个子插件的配置模板入库（`config.example.yaml`），真实 `config.yaml` 一律 gitignore，同步服务器时不必再改配置；`tool_permission_manager` 默认收紧并**修掉一处权限绕过**；`mcp_extension` / `meme_extension` 改名为 `mcp_adapter_demo` / `meme_ops`；日志层与 ncatbot 解耦。

### Added

- **11 个子插件新增入库的配置模板 `config.example.yaml`**（`base_system_tools` / `base_topology` / `context_compactor` / `mcp_adapter_demo` / `meme_ops` / `orphan_tool_fixer` / `pending_tool_fixer` / `qq_adapter` / `tool_attachment_fixer` / `tool_permission_manager` / `web_search`）。模板保持**最小示例**（只展示枚举与格式，不把全部工具/字段列进去），真实取值由各部署环境自行填写。
- **`tool_permission_manager` 新增 `debug` 字段**（`bool`，默认 `true`）：控制「未配置权限的工具」是否打印 warning 日志。
- **`tool_permission_manager` 权限类型扩到五种**（`PermissionT`）：新增 `nobody`（谁都不可用，恒 `False`）与 `passerby`（仅非管理员，`user_id != admin_id`），`is_allowed` 相应扩为五个分支。
- **`mcp_adapter_demo` 子插件**（实验性，`plugins/mcp_adapter_demo/`）：用 `langchain-mcp-adapters` 的 `MultiServerMCPClient` 接入外部 MCP server，`recall_mcp_tools` 节点挂在 `on_before_request`（`priority=MEDIUM`）把 MCP 工具**按名去重**后合并进 `runtime.context["tools"]`；支持 `stdio` / `streamable_http` 两种传输（`models/transports/`），`reusable` 字段用 `Field(exclude=True)` 声明以免污染 `model_dump()`。自带 `README.md`。

### Changed

- **插件改名（破坏性）**：`plugins/mcp_extension/` → `plugins/mcp_adapter_demo/`（入口类 `MCPExtension` → `MCPAdapterDemo`）、`plugins/meme_extension/` → `plugins/meme_ops/`（入口类 `MemeExtension` → `MemeOps`）。`plugin.toml` 的 `enter_class`、两个 `consts/share_store_keys.py` 的 `SHARE_STORE` 命名空间键（`miaoli_bot/subplugin/<新目录名>.…`）、`config.example.yaml` 的 `cp` 路径、插件 `README.md` 与权限表的分组注释同步更新。**必须改键**：包名由目录名推导（`plugin_loader._register_package` 的 `f"{PACKAGE_PREFIX}_{folder.name}"`），不改键 `SHARE_STORE.recall` 直接 `KeyError`。
- **`tool_permission_manager` 的 `enable` 默认值 `false` → `true`**：`config.yaml` 缺失时插件照常生效并打印 warning，权限表为空 → 全部工具被摘掉（默认拒绝），不会因配置缺失而静默放行。
- **`tool_permission_manager/config.yaml` 权限表精简**：74 个 OmniQQ MCP 工具中只保留日常 29 个 —— 发消息与互动 8（`send_private_msg` / `send_group_msg` / `send_msg` / `delete_msg` / `send_poke` / `send_like` / `set_msg_emoji_like` / `mark_msg_as_read`）、看消息 6、查资料 7、文件与图片 6、备注与名片 2；其中 `omniqq_ocr_image` 配为 `nobody`。其余 45 个不再列出。原有 17 条本地工具权限一条未丢。
- **日志层与 ncatbot 解耦**：`core/graph/graph_pipeline.py` 与 `tool_permission_manager/nodes/pick_tools.py` 不再 `from ncatbot.utils import get_log`，改为标准库 `import logging` + `logging.getLogger("<名>")`（不引入中间层模块）；全仓 `get_log` / `ncatbot.utils` 引用清零。
- **根 `README.md` 同步**：版本行、目录树（补 `mcp_adapter_demo`、`meme_extension` → `meme_ops`、`handle_event` → `event_adapter`、`config.yaml 默认值` → `config.example.yaml`）、子插件表（补 `mcp_adapter_demo` 行、权限类型补 `passerby` / `nobody`）、安装依赖列表与依赖表（补 `langchain-mcp-adapters` / `mcp`）。

### Removed

- **`.gitignore` 去掉 `!plugins/*/config.yaml` 例外**：子插件 `config.yaml` 与根 `config.yaml` 一视同仁，不再入库（注释改为「各部署环境的路径/取值不同，不提交；模板见 `config.example.yaml`」）。
- **10 个子插件的 `config.yaml` 移出索引**（`git rm --cached`，工作区文件原样保留）。

### Fixed

- **🔴 `tool_permission_manager/nodes/pick_tools.py` 的权限绕过**：原先「未配置权限的工具」被写成 `if not (permission := permissions.get(tool.name)) and plugin_config.debug:` → 打 warning + `continue`，`debug=false` 时 `and` 短路使 `continue` 不执行，落到 `is_allowed(None, …)` 抛 `AttributeError`；而 `graph_pipeline._dispatch` 对节点异常只 `LOGGER.exception` 后 `continue`（只上抛 `GraphBubbleUp`），于是**写回语句没执行**、`runtime.context["tools"]` 保持全量。实测（真实图，路人身份，权限表只配 1 个工具）：`debug=true` 模型可见 1 个工具，`debug=false` 可见 **91** 个，其中 `bash` / `write` / `replace` / `read_file` 对路人可见。现改为**嵌套分支**——`continue` 无条件执行，`debug` 只决定是否打日志。
- **3 处既有 F541**（f-string 无占位符）：`base_system_tools/tools/bash.py:39,40`（`description=f"缓冲区编码"` / `f"超时时间(秒)"`）与 `utils/sugar.py:48`（`raise RuntimeError(f"插件未启用")`）去掉 `f` 前缀。

### Note

- **为什么权限绕过特别隐蔽**：`debug` 字段自己的描述写着「不推荐生产环境启用」—— 照它建议关掉 `debug` 就等于关掉整套权限控制，且只在日志里留一条 ERROR，机器人行为看起来一切正常。该描述本版已改为「仅影响日志输出，不影响权限判定」。
- **本版验证**：`ruff --select F,E9` 全仓 `All checks passed!`；23 个 YAML 语法全过；11 个 `config.example.yaml` 与 11 个真实 `config.yaml` 均过 pydantic 校验；插件加载 **14/14**；`SHARE_STORE` 新键可读、旧键 `KeyError`；**真实图端到端**（真 14 子插件 + 真 OmniQQ-MCP over SSH + 假模型）`rc=0`，28 个 MCP 工具放行、`final_answer` 正确。
- **部署提醒**：`meme_extension/` 整个目录消失会让服务器上已跟踪的 `plugins/meme_extension/config.yaml` 被 `git reset --hard` 删除，而新来的 `plugins/meme_ops/` 不含 `config.yaml`（已 gitignore）→ `PluginConfig` 拿到 `{}` → `is_enable=false` → 工具照常注册但全部返回「meme被禁用」（**静默失效**）。迁移前先 `cp plugins/meme_extension/config.yaml plugins/meme_ops/config.yaml`，再 `git rm --cached -q plugins/*/config.yaml`，最后 `git fetch && git reset --hard origin/main`。
