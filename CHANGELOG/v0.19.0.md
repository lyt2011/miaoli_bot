# v0.19.0 - 2026-10-18

> 🔧 **`mcp_adapter_demo` 转正为 `mcp_adapter`（破坏性）**，同时把 `reusable` 从 transport 层搬到 server 层、补齐全部导入导出，并修掉接线过程中的七处运行时错误。本版还更新了提示词到 `prompt_v1.6`。
>
> 按 SemVer，0.x 阶段的破坏性变更升 **minor**（与 0.18.0 改名 `mcp_extension` → `mcp_adapter_demo` 的处理一致），因此是 `0.18.2 → 0.19.0`。
> 升级需同步修改：部署目录名、`config.yaml` 里的 `reusable` 位置（从 `transport` 下移到与 `name` 并列）。

## Changed

- **子插件改名（破坏性）**：`plugins/mcp_adapter_demo/` → `plugins/mcp_adapter/`，入口类 `MCPAdapterDemo` → `MCPAdapter`（`plugin.toml` 的 `enter_class` 同步）。`SHARE_STORE` 键命名空间随之更新：
  - `PLUGIN_CONFIG` → `miaoli_bot/subplugin/mcp_adapter.models.plugin_config`
  - `RAW_CONFIG` → `miaoli_bot/subplugin/mcp_adapter.plugin_config`
  - `MCP_ADAPTER` → `MCP_CLIENT_REGISTRY`，值 `miaoli_bot/subplugin/mcp_adapter.mcp_client_registry`
- **`core/MCPAdapter` → `core/MCPClientRegistry`**：文件 `core/mcp_adapter.py` → `core/mcp_client_registry.py`。原名与插件入口类撞车，且 `MCPAdapter` 读起来像「适配器」，实际职责是「管理 client 列表 + 缓存工具」，`MCPClientRegistry` 才贴合语义。
- **`reusable` 从 `BaseTransport` 搬到 `MCPServer`**：它回答的是「这个 server 的 tools 列表会不会变」，与传输方式正交 —— 稳定工具列表的 stdio / http server 都适合开，动态注册工具的都不适合；传输方式只影响复用的**收益大小**（stdio 省子进程启动 + 握手，http 省一次 `list_tools` 往返），不影响**要不要缓存**。配置里现在与 `name` 并列：

  ```yaml
  - name: "omniqq"
    reusable: true
    transport:
      transport: "stdio"
      ...
  ```
- **`reusable` 不再需要 `Field(exclude=True)`**：`exclude` 原本是为了避免污染 `transport.model_dump()`（那个 dict 会直接作为 MCP 连接参数传给 `create_session`，多一个键就 `TypeError`）。搬到 `MCPServer` 后，参数构造只用到 `name` 和 `transport.model_dump()`，`reusable` 天然不参与，因此去掉 `exclude`，字段可正常序列化。
- **`config.example.yaml` 的 `prompt_file` 指向 `prompt_v1.6.md`**（原来还停在 `v1.5`）。

## Added

- **`core/__init__.py` / `protocols/__init__.py` / `models/runtimes/__init__.py`**：三个目录原先没有 `__init__.py`，无法作为包导入，补齐并导出 `MCPClientRegistry` / `ToolObtainanle` / `MCPClient`。
- **`prompt_v1.6.md`**：相对 v1.5 两处调整 —— ① 称呼由「杂鱼」改为「雑魚」；② 换行符说明的措辞由「别人也能看得更舒服」改为「才不是为了让别人看得更舒服的」。

## Fixed

- **`main.py` 方法名**：`mcp_adapter.register(...)` → `registry.register_client(...)`，原方法名在类里不存在（`AttributeError`）。
- **`main.py` 关键字拼写**：`resuable=` → `reusable=`（`TypeError: unexpected keyword argument`）。
- **`main.py` 字段路径**：`mcp.reusable` → `mcp.transport.reusable`（当时 `reusable` 还在 transport 上），本次随字段搬家改回 `mcp.reusable`。
- **`core/mcp_adapter.py` 元素类型不一致**：`self.clients` 声明为 `List[MCPClient]`，但 `register_client` 直接 `append(client)` 存的是裸 client，而去重判断又按 `client_.client` 读 —— 首次注册即 `AttributeError: 'MultiServerMCPClient' object has no attribute 'client'`。改为 `append(MCPClient(client=client, reusable=reusable))`。
- **`core/mcp_adapter.py` 属性名**：`get_tools` 里 `self.client.remove(client)` → `self.clients.remove(mcp_client)`（`self.client` 属性不存在）；循环变量从 `client` 改名 `mcp_client` 后，`if client.reusable` 残留两处未同步，一并改掉（`NameError`）。
- **`on_close` 漏 drop**：只 drop 了 `PLUGIN_CONFIG` / `RAW_CONFIG`，`MCP_CLIENT_REGISTRY` 会残留，`SHARE_STORE` 卸载检查报资源泄露。
- **导入缺失**：`main.py` 缺 `MultiServerMCPClient` / `MCPClientRegistry` / `MCP_CLIENT_REGISTRY`；`core/mcp_client_registry.py` 缺 `Any` / `List` / `MCPClient` / `ToolObtainanle`；`models/runtimes/mcp_client.py` 缺 `dataclass` / `ToolObtainanle`；`protocols/tool_obtainable.py` 缺 `List`；`nodes/recall_mcp_tools.py` 缺 `MCP_CLIENT_REGISTRY`（并删掉未使用的 `MultiServerMCPClient` / `PLUGIN_CONFIG`）。
- **拼写**：`main.py` 的 `MCPAdadpter()` → `MCPClientRegistry()`。

## Note

- **`reusable` 已接线**：`reusable: true` 的 server 在**第一次** `get_tools()` 后从客户端列表移除、工具进 `_cached_tools`，后续只读缓存；`reusable: false` 的每轮重新 `list_tools()`。代价是 `reusable: true` 的 server 若中途更新工具，需重启 ncatbot 才能看到。
- **为什么必须用服务器 Python 验证**：本机是 3.14（PEP 649 注解惰性求值），服务器是 3.12（注解在 `def` 时立即求值）。本版修掉的 `SendOutcome` 类问题在 3.14 下导入成功、3.12 下直接 `NameError`。涉及注解的改动一律在服务器上复验。

  - 三次 `get_tools()` 调用计数：`{'non_reusable': 1→2→3, 'reusable': 1→1→1}`，`clients` 恒为 1、缓存恒为 2 —— 复用语义正确
