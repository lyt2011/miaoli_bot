# v0.50.0 - 2026-11-13

> 🧱 **工具授权从「全局二值开关」改成「按会话授权」**。`Permission` 的 `mode: "allow" / "refuse"` 换成 `allowed`：`"all"` 全部会话放行、`thread_id` 列表只放行指定会话、`null` / `[]` 一律摘除。配置形状不兼容，旧的 `mode` 会被静默忽略。

## Changed

- `plugins/tool_permission_manager/models/permission.py`：`Permission` 字段由 `mode` 改为 `allowed`，类型是新增的 `Allowed = Union[Literal["all"], List[str], None]`；`name` 保留。
- `plugins/tool_permission_manager/nodes/pick_tools.py`：从 `get_config()["configurable"]["thread_id"]` 取本轮会话，逐条判定；不再有 `allow` / `refuse` 二值映射。
- 判定函数抽到 `plugins/tool_permission_manager/utils/is_allowed.py`，签名 `is_allowed(thread_id: str, allowed: Allowed) -> bool`。
- `plugins/tool_permission_manager/models/__init__.py` 导出 `Allowed` 与 `Permission`。

## Removed

- `Permission.mode` 及其 `Mode = Literal["allow", "refuse"]` 别名。老配置里的 `mode` 会被 pydantic 当作多余字段忽略。

## Fixed

- `models/permission.py` 缺 `model_validator` / `List` / `Self` 导入，模块导入即 `NameError`；本机 3.14 的惰性注解把它藏住了，3.12 会直接失败。
- `nodes/pick_tools.py` 缺 `get_config` 导入、`thread_id` 的取法留了空占位。
- `is_allowed` 里写的是 `thread` 而不是 `thread_id`，`allowed` 为白名单列表时必抛 `NameError`。
- 判定分支方向颠倒：原写法是「未授权就 `continue`」，等于把未授权的工具**保留**、把已授权的**摘除**；现在只有「已声明且放行」走 `continue`，其余全部落到摘除。

## Note

- 配置形状不兼容是这次升 minor 的原因：旧 `config.yaml` 不会报错，只会让 `allowed` 落到默认 `[]`，结果是所有工具被摘光、模型一个工具都看不见。升级时先改配置再重启。
- 粒度是「会话」不是「人」：拿到某个私聊的 `thread_id` 等于拿到那个人的授权；群会话的 `thread_id` 对群里所有人一视同仁。
- 实测（桩 `ToolSurface` + 四个工具）：`"all"` 全放行、白名单按 `thread_id` 命中、`[]` 与 `None` 全拒绝、未声明工具摘除并告警。
