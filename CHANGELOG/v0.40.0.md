# v0.40.0 - 2026-11-08

> 🧱 **模型侧配置收进 `llm` 段，新增思考强度档位**。`PluginConfig` 顶层原来平铺着 `provider` / `model` / `providers` 三个键，现在整段挪进 `llm`（`LLMConfig`）；`LLM` 多出 `thinking_efforts`，`LLMConfig` 多出 `thinking`。旧配置文件不再通过校验。

配置分层的动因是键会继续变多：思考强度、温度、超时、重试这些都属于「模型怎么跑」，平铺在顶层会和 `checkpointer` / `sub_plugin` / `channel` 混在一起，等真到了七八个键就分不清谁归谁。收进 `llm` 之后顶层只剩四段，每段自带命名空间。

`thinking_efforts` 是「本项目档位 → 该供应商实际档位」的翻译表，不是能力白名单。因为各家的叫法本来就不一样：DeepSeek 官方认 `minimal` / `low` / `medium` / `high` / `xhigh` / `max` / `ultra`（且服务端自己还有一层映射，`medium` 实际落到 `high`），OpenAI 只认 `minimal` / `low` / `medium` / `high`。表里只写自己要用的档位，键受 `ThinkingEffort` 的八档限制、值是自由字符串。

两个字段**目前只做校验，没有消费**：`api/llm_ops.build_client()` 仍然只传 `base_url` / `api_key` / `model` / `max_tokens`。真正接上要先解决 OpenAI 与 DeepSeek 对 thinking 的处理差异（DeepSeek 用 `reasoning_effort` + `extra_body={"thinking": {"type": ...}}`，OpenAI 只有 `reasoning_effort` 且不认 `off`），这层适配还没做。

## Added

- `models/config/llm_config.py`：新增 `LLMConfig` 模块。字段 `model` / `provider` / `thinking` / `providers`，`model_validator(mode="after")` 的 `check_provider_and_model` 校验供应商、模型确实存在，且 `thinking` 是所选模型 `thinking_efforts` 的键。
- `models/config/provider_config.py`：新增 `ThinkingEffort = Literal["off", "minimal", "low", "medium", "high", "xhigh", "max", "ultra"]`，以及 `LLM.thinking_efforts: Dict[ThinkingEffort, str]`（必填，至少一项）。

## Changed

- `models/config/plugin_config.py`：顶层的 `provider` / `model` / `providers` 三个字段与 `ensure_pm_exist` 校验器删掉，改为一个 `llm: LLMConfig`；`Provider` / `LLM` 的直接导入随之删除，补 `LLMConfig`（破坏性）。
- `api/llm_ops.py`：`get_model_info` / `get_provider_info` / `build_client` / `_get_provider` 四处读取路径从 `config.provider` / `config.model` / `config.providers` 改成 `config.llm.*`。
- `config.example.yaml`：顶层 `provider` / `model` / `providers` 套进 `llm:`，补 `thinking` 与每个模型的 `thinking_efforts`；`thinking_efforts` 写成字典并标注 DeepSeek 官方的映射关系。
- `models/config/__init__.py` / `models/__init__.py`：再导出 `LLMConfig`、`Vision`、`Client`、`ThinkingEffort`。

## Note

- **旧 `config.yaml` 会校验失败**（`llm` 字段缺失），升级时必须把 `provider` / `model` / `providers` 缩进到 `llm:` 下，并给每个模型补 `thinking_efforts`。
- **`thinking_efforts` 里 `off` 这类键在 YAML 里必须加引号**。YAML 1.1 会把裸的 `off` / `on` / `yes` / `no` 读成布尔值，`PyYAML` 的 `safe_load` 会把它变成 `False`，于是字典键成了 `False` 而不是字符串。
- `thinking` 与 `thinking_efforts` 的值目前不参与请求。等到接线时，「本项目档位」这一侧才是配置里该写的词，供应商那一侧由 `thinking_efforts` 翻译过去。

## Docs

- `README.md` / `README/en.md`：配置键表整段重写（`provider` / `model` / `providers` → `llm.*`，新增 `llm.thinking` 与 `llm.providers[].models[].thinking_efforts` 两行，并标注两者尚未被消费）；配置模型化、LLM 接入、目录树、依赖说明里的 `providers[].client` 同步改成 `llm.providers[].client`。
