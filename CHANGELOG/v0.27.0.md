# v0.27.0 - 2026-10-21

> 🧱 **意图注入段在正文末尾追加 `(from <文件路径>)` 来源标记**。让机器人知道这一轮注入的提示词来自哪里、需要时可以去读取，而不是这一轮结束之后就完全不知道上一轮自己做了什么。

标记默认开启，`with_path: false` 退回 v0.26.1 的纯正文注入。

读取失败不会注入：`Path(...).read_text()` 在 `try` 块内，抛异常时该 matcher 这一轮直接不注入，所以不会出现「引用了提示词文件、但文件读不出来」的状态。

注入结果（单个 matcher 命中）：

```
<intent_recognition><miaoli_bot_info>…正文… (from /abs/path/to/miaoli_bot_info.md)</miaoli_bot_info></intent_recognition>
```

## Added

- `plugins/intent_recognition/models/plugin_config.py`：`PluginConfig` 新增 `with_path: bool`（默认 `true`），控制注入时是否追加来源标记。
- `plugins/intent_recognition/nodes/recognize_intent.py`：命中后把 `(from <matcher.file>)` 拼到注入正文末尾再写进 `field_prompts`。

## Changed

- 注入值由「`file` 的原始正文」变为「正文 + 来源标记」。`matchers[].name` 决定的标签名、以及外层 `<intent_recognition>` 段名都不变。

## Note

- 标记里写的是**绝对路径**，会随提示词进入对话上下文。嫌长或不想暴露目录结构时把 `with_path` 关掉即可。
- 同一轮多个 matcher 命中时，各段之间仍以单个 `\n` 连接（`build_prompt` 的 `cr`），外层段与段之间是 `\n\n`（`prompt_builder`）。

## Docs

- 插件 `README.md`：配置字段表补 `with_path` 一行；「读取提示词」一节的代码同步为带开关的写法。
