# v0.17.4 - 2026-10-16

> 🔴 **修复「整条图流水线静默失败」** —— 首次真机运行时 `event_adapter` / `inject_account` / `call_llm` 三个节点接连抛异常，全被 `_dispatch` 吞掉，图照常走到 `on_agent_end`，最后只报出一句误导性的 `agent 被内部中断: 没有可用消息`。

### Changed

- **`qq_adapter/nodes/handle_event.py` → `event_adapter.py`**：文件名与函数名统一改为 `event_adapter`（全仓约定「文件名 = 函数名」），`qq_adapter/main.py` 的导入与 `on_agent_start` 注册同步更新
- **`base_nodes/nodes/output_checker.py`**：`messages` 缺失时的 `Abort` 文案 `没有可用消息` → `上下文列表没有被注入`，避免把「上游节点全炸」误报成「没有消息」
- **`config.example.yaml`**：`prompt_file` 由 `prompt_v1.3.md` 切到 `prompt_v1.5.md`

### Fixed

- **`qq_adapter/nodes/event_adapter.py`（原 `handle_event.py`）**：改为从 `state` 读 `event`。0.17.0 已把事件放进图 `input`（`event._data.model_dump()`），但节点仍在读 `runtime.context.get("event")` → 每轮 `RuntimeError`；同时把 `raise RuntimeError` 换成 `Abort(reason=...)`，走正常中断而不是被当成节点异常吞掉
- **`account_injector/nodes/inject_account.py`**：`cfg.system_prompt` → `cfg.prompt`。0.17.0 已把 `PluginConfig.system_prompt` 字段改成 `prompt` 懒加载属性，节点没跟上 → `AttributeError`，导致 `state["system_prompt"]` 从未被写入，连带 `call_llm` 抛 `KeyError: 'system_prompt'`
- **`qq_adapter/nodes/__init__.py`**：导出指向已删除的 `handle_event` 模块 → `ModuleNotFoundError`；同步改为 `event_adapter`

### Note

- **为什么「一路顺风」到 `on_agent_end`**：`core/graph/graph_pipeline.py` 的 `_dispatch` 对节点异常只记日志后 `continue`（只有 `GraphBubbleUp` 才上抛），而 `base_topology` 给每个事件都挂了 `MINIMUM` 优先级的默认 `Goto` —— 于是「异常 ≡ 无操作 ≡ 继续」；`output_checker` 是链尾唯一的检查点，它的 `Abort` 把真正的 3 个异常盖住了
- **本版验证**：`compileall` rc=0；`ruff --select F,E9` 仅剩 3 处既有 F541；全仓无 `handle_event` 残留、无 `runtime.context["event"]` 读取；**端到端图仿真**（真子插件 13/13 + 假模型）跑通 —— `final_answer` 正确、`state["event"]` 已回填、`system_prompt` 头部为账号信息块、`messages` = `[HumanMessage(事件 JSON), AIMessage]`
- **未处理**：`GraphRuntimeContext.event` 字段现已无人读取（全仓仅 `event_adapter` 曾读 context），是否删除待定
