# v0.22.1 - 2026-10-20

> 🧱 **补齐 `should_compact` 缺失的 `Abort` 导入**。0.22.0 的二次压缩拦截从未生效过。

`should_compact` 的守卫逻辑靠「末条消息带 `compaction` 标志」判断是否已经压过一轮，命中时返回 `Abort`。但该文件只从 `miaoli_pipeline.actions` 导入了 `Goto`，`Abort` 未导入 —— 走到这条分支就是 `NameError: name 'Abort' is not defined`。

异常被 `GraphPipeline._dispatch` 的 `except Exception` 吞掉、打一条 `LOGGER.exception` 后 `continue`，于是守卫什么都没返回，`base_topology` 挂在 `MINIMUM` 的默认跳转接管、跳去 `ON_BEFORE_REQUEST`。**表面行为正确，兜底本身从未执行。**

## Fixed

- `plugins/context_compactor/nodes/should_compact.py`：导入补上 `Abort`。

## Docs

- `plugins/context_compactor/README.md` 与 `plugins/base_topology/README.md`：0.22.0 里写的「目前没有兜底标记」是错的，改为描述实际存在的 `compaction` 标志拦截及其不可靠之处。

## Note

- 拦截判据本身仍是 HACK —— 只看末条消息里有没有 `compaction` 字样。别的节点若在压缩后写一条含该字样的 `HumanMessage` 并跳回 `ON_TURN_START`，会被误拦。之所以够用，是因为当前只有 `compact` 会产出这种消息，且它总把摘要放在 `messages[0]`，`keep_recent_messages` 保留的尾部消息里不会出现。
- 0.22.0 的 `CHANGELOG/v0.22.0.md` 与 `README.md` 项目状态段里的错误描述按「历史记录不改」保留，本版在文档里更正当前态。
