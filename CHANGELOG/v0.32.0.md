# v0.32.0 - 2026-10-31

> 🧭 **`dependences` 从「只存不用」变成真正生效**。子插件元数据一直能写依赖，但加载顺序由 `tp_sort` 决定，而它是个 `return list(plugins)` 的占位 —— 写了也白写。这次把它实现成真的拓扑排序，并把「同一个插件重复声明依赖」挡在元数据校验阶段。

## Added

- **`Plugin.dependences`**（`core/plugin/plugin.py`）：返回 `list(self.metadata.dependences)` 的副本。拓扑排序只关心名字，这个属性负责给出依赖名单。
- **`RepeatDependenceError`**（`core/plugin/errors/repeat_dependence_error.py`）：新增异常类型，继承 `BasePluginError`。
- **`repeat_dependence_checker`**（`core/plugin/models/plugin_metadata.py`）：`mode="after"` 校验器，同一插件里声明两次同名依赖时报错，消息里列出多余的那几个（`['a', 'a', 'a']` 报 `['a', 'a']`）。
- **`GraphRuntimeContext.custom_status` / `custom_mapping`**（`models/graph_runtime_context.py`）：给节点标记「这一轮是谁触发的」（`main` / `is_waking`）。字段已进类型定义，具体消费方后续再接。
- **`main.py` 的 `ainvoke` 带上 `custom_status: ["main"]`**：用户消息路径显式标记。

## Changed

- **`tp_sort` 实装**（`core/plugin/loader.py`）：改前是 `return list(plugins) # HACK: 懒得写 直接返回`，即什么都不排。现在按 `package_name` 稳定排序后逐轮剥离依赖，输出「依赖在前」的顺序。
- **`tp_sort` 的失败路径**：改前没有失败路径；现在遇到环或缺失依赖时抛 `RuntimeError`，并把卡住的插件名全部列出来。

## Note

- **同层顺序由入口的 `sorted` 钉死**：拓扑排序只保证偏序，同层内按插件名排列，否则每次进程启动的加载顺序都会变。
- **报错分不清「环」还是「缺失依赖」**：两者表现一样（都没法继续），所以并列在一条消息里。`plugins_mapping` 是为区分它们留的，目前没人消费。
- **`tp_sort` 一轮只摘掉一个同名依赖**（`if name in deps: deps.remove(name)`）：重复声明在元数据层就被挡掉了，所以走不到这条路；若绕过 pydantic 直接改 `metadata.dependences`，会误报成环。
