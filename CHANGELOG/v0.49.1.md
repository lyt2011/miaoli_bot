# v0.49.1 - 2026-11-13

> 🔧 **修 0.49.0 提示词里的一处行为回归**：模型开始用发送工具发普通对话，同一条内容在 QQ 里出现两遍，而且工具那条不走空行分条。

## Changed

- `plugins/miaoli_bot_adapter/data/output_protocol.md` 的 `### 工具通道` 补三段约束：四类用途以外不用发送工具、普通对话写在正文里；工具发出的内容不会按空行分条，分条只发生在正文里；用了发送工具的回合，正文里不要再把同一句写一遍。

## Fixed

- 实测现场（`group-1046279455`）：模型在同一轮里调 `send_meme_to_qq` 与 `send_message_to_qq`，把「就戳我一下然后什么都不说？\n有事说事喵」用工具发出（单换行、整段一条），随后又在正文里写了同一句话（双换行、被切成两条）—— 对方收到的是「表情包 + 一条不分条的文本 + 两条分条的文本」。

## Note

- 成因是 0.49.0 把「正文直出、工具只用于四类」从 `## 回复通道` 拆成两处：约束留在 `## 通用机制`，用途单列在 `### 工具通道`，两者隔了两个小节，模型只读到用途就顺手把文本也用工具发了。这次把约束和用途放回同一节。
- 分条本身没有坏：正文那条 `\n\n` 被正确切成两条，出问题的是走工具的那条路径。提示词文件每轮读取，改完不需要重启。
