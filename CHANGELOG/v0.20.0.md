# v0.20.0 - 2026-10-18

> 🧱 **新增 `miaoli_bot/api/` 门面层，子插件不再直接操作 `SHARE_STORE`**：34 个子插件文件里的 77 处 `SHARE_STORE.set / drop / recall` 全部改为调用 `miaoli_bot.api` 的具名函数；根 `__init__.py` 的导出面同时收窄为 `api` / `models` 两项。**破坏性**：仍按老写法 `from miaoli_bot import SHARE_STORE` / `GraphState` 的自定义子插件会 `ImportError`。

## Added

- **`api/` 门面层（Published Interface）**，四个模块共 14 个导出：
  - `api/account_ops.py` —— `get_admin_id` / `get_bot_id` / `get_admin_nickname` / `get_bot_nickname`，从根配置派生账号信息。
  - `api/store_ops.py` —— `store_recall` / `store_drop` / `store_update` / `store_set`，`SHARE_STORE` 的四个操作转发，附「不可覆盖 / 不可新建」的语义约束。
  - `api/platform_ops.py` —— `get_ncatbot_api`，取框架运行时句柄。
  - `api/sugar.py` —— `get_model_info` / `get_prompt`，从根配置派生模型信息与提示词。
  - `api/__init__.py` 另转发 `utils` 的三个发送封装（`private_easier_send` / `group_easier_send` / `easier_send`），子插件只需 `from miaoli_bot.api import ...` 一个入口。

## Changed

- **34 个子插件文件改走 `api`**，`SHARE_STORE` 直接引用清零（`plugins/` 下残留 0 处）：`store_set` 23 次、`store_drop` 23 次、`store_recall` 22 次、`get_ncatbot_api` 7 次、`get_admin_id` 1 次、`get_model_info` 1 次。
- **`GraphState` / `GraphRuntimeContext` 的导入改到所属层**：21 个文件的 `from miaoli_bot import GraphState, GraphRuntimeContext` → `from miaoli_bot.models import ...`。此前这两类名字混在根包里，与其定义位置 `models/graph_state.py` / `models/graph_runtime_context.py` 不符。
- **`context_compactor/nodes/compact.py`** 不再自己从根配置里链式取 `providers[provider].models[model]`，改用 `get_model_info()`。
- **`tool_permission_manager/nodes/pick_tools.py`** 不再自己挖 `recall(ROOT_PLUGIN_CONFIG).account.admin_id`，改用 `get_admin_id()`。
- **7 个工具文件**（`qq_platform_tools/*` 六个 + `meme_ops/tools/send_meme.py`）删掉已失效的 `from miaoli_bot.consts import NCATBOT_API`。

## Removed

- **根 `__init__.py` 的导出面从 8 项收窄为 2 项**：`consts` / `SHARE_STORE` / `GraphState` / `GraphRuntimeContext` / `PluginProtocol` / `StoreProtocol` / `BaseBotError` / `PipelineStopDispatch` 不再从根包重导出，只留 `api` 与 `models`。这是本版的**破坏性**部分 —— 收窄的目的就是让「子插件该从哪里拿东西」只有一条路。
- **`utils/sugar.py` 删 4 个函数**：`get_thread_id` / `get_sub_plugin_root` / `get_model_config` 零引用；`get_tool_calls` 的 4 处调用全部内联为 `(message.tool_calls or [])`。文件只剩 `concatenate_id`，`utils/__init__.py` 的导出 8 → 4 项。副产物是 `pending_tool_fixer` 与 `orphan_tool_fixer` 两个子插件不再需要依赖主包 `utils`。

## Fixed

- **`api/store_ops.py:22` 的 `NameError`**：哨兵常量从 `DEFAULT` 改名为 `_UNSET` 时漏改了这一处引用，`store_recall` 一旦走到缺键分支就崩。
- **`api/store_ops.py` 的 `store_recall` 忽略 `default` 参数**：原实现写死 `SHARE_STORE.recall(key, default=_UNSET)`，把用户传入的默认值完全丢弃，于是 `store_recall(key, default='fallback')` 也会抛 `KeyError`。改为透传 `default=default` —— 该写法恰好依赖「两个 `_UNSET` 不是同一实例」：用户不传时传下去的是本模块哨兵，底层当作「有默认值」原样返回，再被 `is _UNSET` 捕获并报错；用户传了则正常返回其值。

## Note

- **`store_set` 与 `SHARE_STORE.set` 语义不同**：前者「键已存在就抛 `KeyError`」，后者「直接覆盖」。正常路径安全（ncatbot 热重载走 `__unload__()` → `on_close()` → `on_load()`，`drop` 先跑），但 `load_all()` 是顺序执行且无 try/except（`main.py:90` 注释已标注「一个插件错误会全炸完」）：某子插件 `on_load` 中途抛异常时，前面已 `set` 的键会残留，修好重载会撞 `KeyError`，只能重启进程 —— 原来 `set` 能自愈。
- **`get_ncatbot_api` 归 `platform_ops` 而非 `sugar`**：`sugar` 里的 `get_model_info` / `get_prompt` 都是从根 `PluginConfig` **派生**的纯数据，而 `get_ncatbot_api` 取的是**框架运行时句柄**，与配置无关，放一起语义不清。
- **`get_model_info()` 保持无参**：曾考虑加 `provider_name` / `model_name` 可选参数以适配 `compact.py` 的动态模型，核实后放弃 —— `state["provider"]` / `state["model"]` 的唯一写入点是 `main.py:139`，取值就是 `plugin_cfg.provider` / `plugin_cfg.model`，与 `get_model_info()` 内部所用字段完全相同，参数永远等于默认值。
- **`store_recall` 与底层 `_share_store.recall` 各有一套哨兵**（模块级 `_UNSET` vs 内部 `_UNSET`），当前靠 `is` 判定的差异工作正常，未统一。
