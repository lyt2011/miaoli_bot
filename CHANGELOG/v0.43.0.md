# v0.43.0 - 2026-11-10

> 🧱 **通道消息把整份内容交给图，不再先压成一段文本**。`BaseChannelMessage` 新增抽象方法 `to_content()`，与 `to_text()` 并存 —— 纯文本通道返回字符串，多模态通道返回内容块列表；顺带把 `safe_run_graph` 的调用形状整成「`state` + `context` + 仅关键字 `thread_id`」，并把 `ChannelDrainResult` 与 `_drain_c` 收进 `core/`（破坏性）。

0.42.0 把「一轮取空、一轮跑完」摆平之后，入口还剩一处写死的地方：`main.py` 只会拿 `to_text()` 的返回值建 `HumanMessage`，于是纯图片消息在判空那一步就被当成空消息丢掉 —— 内容其实在，只是 `to_text()` 按定义返回空串。这一版把「进图的内容」从文本提升成协议级的 `to_content()`，`to_text()` 原样留着；同时把上一版留在 `main.py` 里的类型别名、以及 `channel_surface.py` 里那个私有协程，分别收拢进 `core/notice_channel`，并给 `ShareStore` 与工具注册器补了用例。

## Added

- **`protocols/channel/message.py`：新增抽象方法 `to_content() -> Union[str, List[Dict[str, Any]]]`**，与 `to_text()` 并列，两个都是 `@abstractmethod`；同时补上 `typing` 的 `Any` / `Dict` / `List` / `Union` 导入。纯文本通道返回字符串，多模态通道返回内容块列表 —— 形状与 `BaseMessage.content` 对齐，主包原样塞进 `HumanMessage`，不再自己拼。
- `core/notice_channel/helpers.py`：新文件，`_drain_c()` 从 `channel_surface.py` 迁入（见 `Changed`）。
- `core/__init__.py`：`ShareStore` 加入导出，`__all__` 同步。
- `tests/conftest.py`：`clean_store` 自动 fixture，每个用例执行前后各 `SHARE_STORE.clear()` 一次，避免全局单例在用例之间串数据。
- `tests/test_store.py`：4 个用例覆盖 `ShareStore` 的存与取（含 `default` 参数与缺键 `KeyError`）、`clear()` 换新字典且 `is_empty()`、`keys()` / `values()` 的数目与引用、以及 `_store` 是实例属性而非类变量。
- `tests/test_tool_registry_family.py`：4 个用例覆盖 `ToolRegistry` 的注册与同名顶替、注销（含改过 `name` 之后注销不掉的已知缺陷）、`to_surface()` 的快照语义、`ToolSurface.add()` 只动快照不动注册表。

## Changed

- **进图的内容**：`main.py` 的 `_run_channel_graph` 改用 `message.to_content()` 的原样返回构造 `HumanMessage`（原来是 `to_text()`），字符串与内容块列表都直接交给 langchain。
- **空消息判据**：从 `to_text().strip()` 改成 `not content or (isinstance(content, str) and not content.strip())` —— 列表只判空、字符串才 `.strip()` 判长度。只带图片块、`to_text()` 是空串的消息不再被丢掉。
- **`safe_run_graph` 签名**：`(state, thread_id, context)` → `(state, context, *, thread_id)` —— `context` 提到第二位，`thread_id` 变成仅限关键字。
- **`ChannelDrainResult` 迁出 `main.py`**：类型别名 `Dict[BaseChannel, List[BaseChannelMessage]]` 从 `main.py` 的模块级挪进 `core/notice_channel/channel_surface.py`，`main.py` 改为从 `.core` 导入；`core/__init__.py` 与 `core/notice_channel/__init__.py` 的导入与 `__all__` 同步补上。
- **`_drain_c` 迁进 `helpers.py`，超时改由它自己判**：`channel_surface.batch_drain` 只留 `asyncio.gather(..., return_exceptions=True)` 加「按元组过滤」；单通道的 `asyncio.wait_for(c.drain(), timeout=atimeout)` 挪进 `_drain_c` 内部，签名加上 `timeout`，返回类型改成 `Optional[Tuple[BaseChannel, List[BaseChannelMessage]]]`。
- **超时与异常的落点**：原来超时由外层的 `wait_for` 抛（`_drain_c` 只 `except BaseException` 记日志后重抛），现在 `asyncio.TimeoutError` 记一条 `warning`（带渠道名与超时秒数）、其它 `Exception` 记 `exception`，两者都返回 `None`，由 `batch_drain` 当成「这一路没有结果」过滤掉；`except` 收窄到 `Exception`，`CancelledError` 不再被吞。落进 `batch_drain` 的映射仍然只有成功的那几路。
- **回复的匹配式**：`case {"messages": messages}` 加内部 `if` 改成 `case {"messages": [*_, last]} if isinstance(last, AIMessage)`。末条不是 `AIMessage`、或 `messages` 为空时不再静默跳过，落到 `case _` 打一条 error —— 与「返回了没有被 `match-case` 匹配的对象」共用同一条日志。
- `main.py` 的 `typing` 导入收窄成只 `Union`：`Dict` / `List` 随 `ChannelDrainResult` 一起不再需要。

## Fixed

- **只带图片块的消息不再被丢掉**：0.42.0 用 `to_text().strip()` 判空，而纯图片消息的 `to_text()` 按定义就是空串，整条消息在判空那一步被丢、一次图都不跑；现在按 `to_content()` 判空，内容块列表非空就进图。

## Note

- **这是破坏性变更**：`to_content()` 是 `@abstractmethod`，任何 `BaseChannelMessage` 实现都得补上 —— 平级的 `miaoli_qq_channel` 要同步。
- **`safe_run_graph` 的调用方要改**：第二个位置参数从 `thread_id` 变成 `context`，`thread_id` 只接受关键字。子插件从 `miaoli_bot.core` / `api` 拿到这个函数，按老顺序传会把 `thread_id` 传进 `context`。
- **`to_text()` 在本仓库内已无调用点**：留作协议方法给通道实现与其它调用方，主包进图只认 `to_content()`。
- `ShareStore` 从 `core` 导出只是补了个类出口；子插件仍然不许直接操作容器，一律走 `miaoli_bot.api` 的 `store_*`。
- `tests/test_tool_registry_family.py` 里留着一条 `REVIEW:` 注释，记录「以 `tool.name` 为键注销、对象改过 `name` 就删不掉」的已知缺陷 —— 用例目前按缺陷现状断言，修好之后要连注释一起删。
