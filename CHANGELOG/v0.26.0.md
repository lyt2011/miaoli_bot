# v0.26.0 - 2026-10-21

> 🧱 **新增 `any_keywords` / `min_keywords` 两种规则，并统一了四种规则的命名语义：名字一律回答「要几个命中」**。旧名 `keyword` / `keywords` 只说「关键字」，读不出量词，`keywords` 还带着一个语义别扭的 `count`。破坏性：`mode` 字面量与类名全部改变，旧配置不再被接受。

四种规则现在的分工是**命中数量**，不是「命中方式」：

| mode | 类 | 判定 |
| --- | --- | --- |
| `single_keyword` | `SingleKeywordRule` | 单个 `word`，`word in data` |
| `any_keywords` | `AnyKeywordsRule` | 任意一个 `words` 命中 |
| `min_keywords` | `MinKeywordsRule` | `words` 命中数量 `>= count` |
| `regex` | `RegexRule` | `re.search`，命中子串即可 |

`min_keywords` 这个名字是为了让 `count` 说得通 —— 原先它叫 `keywords`，只说了「多个关键字」，`count` 从哪来、为什么是下限都得靠猜。`min` 直接点明那是**下限**：至少命中几个。

顺带补齐了「或」的直白写法：以前想表达「任意一个命中」只能写 `keywords` 且不写 `count`（依赖 `count` 默认 1 的巧合），现在有 `any_keywords`，不必再靠巧合。

## Changed

- `mode` 字面量改名：`keyword` → `single_keyword`，`keywords` → `min_keywords`。判别式联合按新字面量分派。
- 类名与文件名跟随改名：`KeywordRule` → `SingleKeywordRule`（`rules/single_keyword.py`）、`KeywordsRule` → `MinKeywordsRule`（`rules/min_keywords.py`）。
- 四个 rule 的 `__all__` 与导入统一按文件名排序。

## Added

- `models/rules/any_keywords.py`：`AnyKeywordsRule`，`words` 任意一个命中即 `True`（`any()`）。
- `models/rules/min_keywords.py`：`MinKeywordsRule`，`words` 命中数量 `>= count`（原 `KeywordsRule` 的逻辑，改名）。

## Removed

- `models/rules/kw.py` / `models/rules/kws.py`：文件名随类名迁走。

## Note

- **破坏性**：旧配置里写 `mode: "keyword"` 或 `mode: "keywords"` 会直接抛 `union_tag_invalid`，需改成 `single_keyword` / `min_keywords`。该插件 `enable` 默认 `false`，且 0.25.1 尚未部署到服务器，实际影响范围为零。
- `min_keywords` 的 `count` 默认 1 时，「至少 1 个」与「任意一个」等价 —— 想表达「或」请写 `any_keywords`，不要依赖这个巧合。
- `.gitignore` 新增 `data/intent_prompts/`：意图识别要注入的提示词属于本地私有文案，不入库。`config.example.yaml` 里的路径仍指向该目录，部署时自行放置。

- `config.example.yaml`：示例改用新 `mode`，并补 `any_keywords` 一例。
