# v0.49.0 - 2026-11-13

> 🎭 **人设和输出协议按「脱离框架还成不成立」重新划了边界**。原来的划分标准是「形态 vs 人格」，于是语序、标点、接话手法、敷衍装傻全被当成形态留在协议里 —— 结果是只注入人设时，她知道自己是谁，却不知道话该说多长、对方只发一张图该怎么应、被挑错要不要道歉，语气有一半装备在协议里。这一版把标准换成「把框架拿掉之后这条还成立吗」：协议只剩渠道与工具机制，其余全部回到人设，并且改写成散文而非条目。

## Changed

- `plugins/miaoli_bot_adapter/data/output_protocol.md`：2427 → 637 字符（1746 → 445 汉字），10 节收缩成 2 节。`## 长度` / `## 接话` / `## 松弛` / `## 符号` / `## 分寸` / `## 标点` / `## 语序` / `## 对方只发来这些` 整节移出，其中教行为的条款并入人设。剩下 `## 通用机制`（正文直出，不重复发送；没调到工具就不能说已经办成）与 `## 本渠道：QQ 适配器`（`### 消息边界` / `### 输入形态` / `### 输出格式` / `### 工具通道`）。渠道机制单独成层，换 channel 时整层替换，人设一个字不动。
- `plugins/miaoli_bot_adapter/data/SOUL.md`：1258 → 1113 字符（971 → 932 汉字），4 节变 4 节但条目归零：`## 身份` / `## 外貌` / `## 脾气` / `## 口吻` 合并重写成 `## 我是谁` / `## 怎么对人` / `## 怎么说话` / `## 优先次序`，31 条 bullet 全部改成散文段落。性格由「优先级 + 倾向」表达，不再由「对方 X → 我 Y」的条目表表达。
- `core/compact/utils/`：9 个文件收成 6 个。`base_calculate` → `estimate_message_tokens`，`calculate_text` → `estimate_text_tokens`，`full_base_calculate` → `estimate_content_tokens`；`calculate_array` 与 `calculate_image_url` 降为 `estimate_content_tokens.py` 内的私有 `_estimate_blocks`。
- 0.47 现在只有一个来源：`core/compact/consts/tokens.py` 的 `DEFAULT_TEXT_RATIO`，`estimate_message_tokens` 与 `estimate_text_tokens` 都从它取，不再有第二份字面量。
- `plugins/base_nodes/nodes/compact.py` 与 `core/compact/token_pruner.py`：调用点改用 `estimate_message_tokens`。
- `manifest.toml` / `README.md` / `README/en.md`：版本号与压缩链路的函数名同步。

## Added

- `core/compact/utils/estimate_content_tokens.py`：全量估算入口（含多模态块）。压缩链路不使用它 —— 压缩只按纯文本计 token，图片等非文本块对门槛贡献 0。
- `core/compact/utils/estimate_text_tokens.py`：唯一的文本估算实现，返回未取整的 float，取整交给调用方。
- `core/compact/consts/tokens.py` 增加 `DEFAULT_TEXT_RATIO`（0.47 的规范化名字）。

## Removed

- `core/compact/utils/calculate_bytes.py`：参数完全未被使用，函数体等价于返回常量。
- `core/compact/utils/calculate_array.py`、`calculate_image_url.py`、`calculate_text.py`、`base_calculate.py`、`full_base_calculate.py`：内容分别并入 `estimate_content_tokens` / `estimate_text_tokens` / `estimate_message_tokens`。
- `core/compact/consts/tokens.py` 的 `DEFAULT_TEXT_RADIO`（拼写错误的常量名）。

## Fixed

- 多模态文本块原来把整个 dict 传给文本估算函数，算出来是「字典键数 × 0.47」，与文字长度无关；现在按块里的 `text` 计算。
- OpenAI 风格图片块（`image_url` 是 `{"url": ...}`）原来抛 `AttributeError`，现在按常量计。
- 图片块不再解 base64：原实现解出一整段二进制后丢弃，一张图几十万字符，每轮每条消息白解一次。

## Note

- 压缩门槛口径未变：仍是纯文本。`estimate_message_tokens` 走 `extract_content`（只取文本块），AIMessage 额外拼 `tool_calls`；改动前后在 10 组真实消息上逐位对拍一致。
- 提示词的效果用 4 个真实会话（`private-3757973483` / `private-3640942712` / `group-771635742` / `group-1046279455`）、每会话最多 20 个回合边界、每回合 6 次采样、共 2250 次调用比对过。一个反直觉结果：人设从 1989 汉字砍到 932 汉字之后，输出反而变长 39%（25.8 → 35.9 汉字/条）；在散文里补回一句「说完就停，不为了显得周到把话补齐」能压回 33.4，一句话换来 7%。
- 句号串表达「不评价」、对方丢符号或说无意义的话时「按印象与心情三选一（抄回去 / 回几个标点 / 一个表情包）」、问代码只给建议或小段伪代码 —— 这三条是这次实测里最容易被固定脚本化的地方，写成了倾向而不是步骤，且没有引用任何具体插件。
