# v0.51.0 - 2026-11-14

> 🧱 **压缩链路的剪枝从「可变对象」收成一个函数，`pending_tool_fixer` 砍掉全部配置**。`TokenPruner` 既当容器又当操作器，调用方要自己留快照、自己算差值；一个模块级 `prune_messages(messages, retain_tokens)` 一次返回剪枝前后 tokens 与剪枝结果就够，且按索引删除避免了 `list.remove` 的平方级开销。`pending_tool_fixer` 那边配置项只有 `enable` / `fix_message` 两个，改文案还得改部署环境的 `config.yaml`，不如把文案放进 `consts/`、节点永远注册。

## Added

- `core/compact/utils/prune_messages.py`：`prune_messages(messages, retain_tokens) -> (tokens_before, tokens_after, messages_after)`。从最旧一端按预算删，`SystemMessage` / `ToolMessage` / 带 `tool_calls` 或 `invalid_tool_calls` 的 `AIMessage` 一律不剪，入参不被改动。
- `plugins/pending_tool_fixer/consts/fix_texts.py`：`COMMON_FIX_TEXT`（schema 正确、只是没跑完）与 `INVALID_FIX_TEXT`（参数不是合法 JSON，压根没调成）。

## Changed

- `core/compact/utils/estimate_content_tokens.py` / `estimate_message_tokens.py`：返回值从 `int` 改成 `float`，辅助函数不再替调用方取整；`estimate_message_tokens` 从「只算正文」改成「正文 + 多模态内容 + `tool_calls`」，图片块按 `DEFAULT_PAYLOAD_TOKENS`（1440）计。
- `core/compact/utils/estimate_content_tokens.py`：去掉两处 `int()`（字符串分支与多模态汇总各一处），直接返回 `estimate_text_tokens` 给出的 float。
- `core/compact/runtimes/compact_success.py`：`tokens_before` / `tokens_after` 从 `int` 改成 `float`。
- `core/compact/compact_now.py`：剪枝改成一次 `prune_messages(messages, retain_tokens)` 拿全三项，出口不再 `math.ceil`，`tokens_*` 原样透传给 `CompactSuccess`。
- `core/compact/utils/extract_tool_calls.py`：把 `invalid_tool_calls` 也展开成 `$name($args)` 行（`args` 是模型吐出的原始字符串），去掉入口的 `assert isinstance(message, AIMessage)` —— 两个调用方都先判过类型。
- `plugins/pending_tool_fixer/main.py`：`on_load` 不再校验 `PluginConfig`、不再 `store_set`，直接注册 `fix_pending_tool_call`（`MEDIUM`）；`undo_list` / `on_close` 保留。
- `plugins/pending_tool_fixer/nodes/fix_pending.py`：修复范围从「`tool_calls` 里没返回的」扩到「`tool_calls` 与 `invalid_tool_calls` 里没返回的」，两类各用各的正文。
- `plugins/pending_tool_fixer/utils/sugar.py`：`fix_tool_message` 的参数注解放宽到 `Union[ToolCall, InvalidToolCall]`。

## Removed

- `core/compact/token_pruner.py`：`TokenPruner` 类整体删除，`from_messages` / `get_messages` / `get_remaining_tokens` / `prune` 四个入口合并成 `prune_messages`（破坏性：`core.compact` 不再导出 `TokenPruner`）。
- `plugins/pending_tool_fixer/` 下的 `config.yaml`、`config.example.yaml`、`models/`（`PluginConfig`）、`consts/share_store_keys.py`（`PLUGIN_CONFIG` / `RAW_CONFIG`）—— 插件不再有配置，也就没有要存进 `SHARE_STORE` 的东西（破坏性：旧的 `enable` / `fix_message` 静默失效）。
- `core/compact/compact_now.py` 的 `import math`。

## Fixed

- 单条 1~2 字符的消息（`喵` / `嗯嗯`）估算结果被两次 `int()` 抹成 0 token；现在 `喵` 记 0.47、`嗯嗯` 记 0.94。
- `fix_pending_tool_call` 里 `build_tool_message`、`tool_call`、`LOGGER` 三个未定义名（`NameError`）。
- `fix_pending_tool_call` 返回 `{"messages": repaired}` 漏了 `Overwrite`：`GraphState.messages` 是 `add_messages`，整表返回会被当成新消息追加。
- 只带 `invalid_tool_calls` 的 `AIMessage` 原来被算作可剪消息，剪掉后它的 `ToolMessage` 因不可剪而留下，成为孤儿；`prune_messages` 现在把它和带 `tool_calls` 的一样保护起来。

## Note

- 旧 `TokenPruner.prune` 用 `list.remove` 按值删除，每次都要走 pydantic 的 `__eq__` 逐字段比较，整体是 O(n²)：630 条 15.9 ms、100 万条外推 19.3 小时。`prune_messages` 用「索引 → 消息」的字典 + `del dict[index]`，O(1) 删除：630 条 0.8 ms、100 万条实测 1.39 s。
- 剪枝无解的情形仍然会返回超标结果 —— 不可剪的消息（`SystemMessage` / `ToolMessage` / 带 `tool_calls` 的 `AIMessage`）自身就超过 `retain_tokens` 时，可剪的会被删光而总量依然超标。调用方拿到的 `tokens_after > retain_tokens` 就是这个信号，目前 `compact_now` 不做判定。
