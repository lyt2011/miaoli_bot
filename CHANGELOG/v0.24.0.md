# v0.24.0 - 2026-10-20

> 🧱 **`meme_ops` 提示词外置成文件、`enable` 真正生效**。此前 `is_enable` 只被工具内部读来判断返回值，关闭后工具照样注册进工具表、`inject_helper` 照样注入提示 —— 开关等于没关。

## 提示词从常量搬到文件

`inject_helper` 原来注入的是 `nodes/inject_helper.py` 里的 `MEME_HELPER` 常量，改提示词要动代码。现在改成 `data/meme_helper.md`，`PluginConfig.helper` 懒加载读取（每次访问读一次文件，不做缓存），配置文件用 `helper_path` + `encoding` 指定。

新提示词除了「先 `list_memes` 再 `send_meme_to_qq`」的回复工作流，还加了归档判据 —— 要求模型归档前逐条对照「是否传递情绪 / 是否涉及隐私 / 是否引起争议 / 是否含不良内容」，并明确禁止靠 image segment 的 `sub_type` 判断。

## `enable` 真正生效

`is_enable` 原来只被 5 个工具内部读来判断「返回禁用提示还是干活」，工具本身照常注册，`inject_helper` 也照常注入。所以配置写 `false` 时：工具还在工具表里，模型能看见也能调，只是每次调用拿到一句「meme被禁用」；`meme_helper` 段照常进提示词。

现在 `on_load` 在写 store 之后加了一道判断，关闭时直接 `return`，**工具与节点都不注册**。这也让「关闭 + 不填 `helper_path`」真正成立 —— 之前 `inject_helper` 无条件注册，`helper` 访问到 `None` 会抛 `TypeError`，虽然被 `_dispatch` 吞掉但每轮打一条异常日志。

## 破坏性

- 配置键 `is_enable` → `enable`，旧键名不再被识别
- 新增 `helper_path`（绝对路径，启用时必填）与 `encoding`

已有部署需同步改 `config.yaml`。

## Added

- `plugins/meme_ops/data/meme_helper.md`：表情包扩展帮助文档，含回复工作流与归档判据。
- `models/plugin_config.py`：`helper_path` / `encoding` 两个字段；`helper` property 懒加载读文件。
- `models/plugin_config.py`：`init_helper` 校验 —— 启用时 `helper_path` 为空直接 `ValueError`。

## Changed

- `nodes/inject_helper.py`：注入内容从 `MEME_HELPER` 常量改为 `store_recall(PLUGIN_CONFIG).helper`。
- `main.py`：`on_load` 增加 `enable` 判断，关闭时不注册任何工具与节点。
- `tools/*.py`：5 个工具的判断改读 `plugin_config.enable`。
- `config.example.yaml`：同步 `enable` / `helper_path` / `encoding`，补绝对路径提醒。

## Removed

## Fixed

## Note

- `helper` 每次访问都读一次文件，不做缓存 —— 换提示词不用重启，但每轮会多一次磁盘读。文件 662 字节，开销可忽略。
- `init_helper` 只校验路径非空，不校验文件存在。路径写错要到 `helper` 被访问时才 `FileNotFoundError`。
- 新提示词实测 5 个场景 × 2 次：负例（擦边 / IP 隐私 / 普通截图）6/6 正确不归档，正例 3/4 归档。唯一失分是 `sub_type=0` 的真表情包 1/2 —— 结尾「可以归档也可以不归档，完全基于人物设定」与「合格就归档」存在对冲。
