# v0.39.0 - 2026-11-06

> 🧱 **消息入口从主包搬到可插拔的「通道」，图管线并回主包，`core/` 重新分层，注册一律「调用返回注销函数」**。QQ 那一侧（事件缓冲、消息段解析、平台工具、账号注入）拆成平级插件 `miaoli_qq_channel`，主包从此只认 `BaseChannel`，不再认 ncatbot 的事件类。

1.0.0 的动因是职责收口：0.36.0 的主包同时扮演「框架」与「某一个平台的适配层」—— 它挂着 `@registrar.on_message`、自己解析 OB11 消息段、自己拼 QQ 账号信息、自己按会话切块发送。这四件事把框架和平台绑死，换一个消息来源就得改主包。这一版把「收消息」抽成 `BaseChannel` / `ChannelMessage` 两条抽象，主包只负责注册表、一轮内快照与跑图；QQ 的具体实现整体迁到平级插件。

同一轮里另外两件事是同源的：图管线原本是独立仓库、独立安装的外部包 `miaoli_pipeline`（没上 PyPI，`pip_dependencies` 写不了，部署要额外 `pip install /path/to/miaoli_pipeline`，本机与服务器各装一份、版本各自漂移），现在它的源码就是主包里的 `core/graph_pipeline/`；注册方式原本给每个图事件配一对 `on_<事件>()` / `remove_<事件>()`，每加一个事件要在三处各补一次、`on_close` 的摘除顺序还得手工对齐 `on_load` 的注册顺序，现在只剩 `on(event, func, priority)` 与 `register_tool()` / `register_channel()` / `store_set()`，一律返回注销函数，子插件收进 `self.undo_list` 即可成对。

配置与状态也随之下岗：`account` / `split` / `typing` 三段删除（账号注入迁出、发送侧下线），`GraphState` 的 `event` / `final_answer` 换成 `raw_input`，`GraphRuntimeContext` 的 `tools` 换成 `tool_surface`。

## Changed

- **图管线并回主包**：外部独立包 `miaoli_pipeline`（源码在另一个仓库、部署要单独 `pip install /path/to/miaoli_pipeline`）→ `core/graph_pipeline/`：`graph_pipeline.py`（`GraphPipeline`：`register_handler` 返回注销函数 / `wire` / `compile` / `bind` / `ainvoke`）、`actions/`（`BaseNodeAction` 与 `Continue` / `Goto` / `Abort`）、`channels/section_patch.py`（`SectionPatch`）、`runtimes/handler.py`（`Handler` 数据类：`event` / `priority` / `function`）。`main.py` 与各子插件的导入从 `miaoli_pipeline.*` 改到 `miaoli_bot.core` / `miaoli_bot.consts`。
- **`core/` 重新分层**：`core/registries/handler_registry.py` → `core/handler_registry.py`；`core/registries/tool_registry.py` → `core/tool/registry.py`（`remove(name, ignore_error=)` → `unregister(tool)`，并新增 `to_surface()`）；`core/_share_store.py` → `core/share_store.py`（公开名，不再带下划线前缀）；`core/plugin/models/topology_runtime/` 合并成单文件 `core/plugin/models/plugin_topology_runtime.py`。
- **抽象与异常集权**：`core/plugin/protocols/` / `core/scheduler/protocols/` / `core/check_pointer_adapters/protocols/` 三个目录的抽象搬到顶层 `protocols/`；`core/plugin/errors/` 的五个加载期异常（`BasePluginError` / `NotAPackageError` / `MetadataMissingError` / `EntryClassNotFound` / `RepeatDependenceError`）搬到顶层 `errors/`，`AgentAborted` 从 `miaoli_pipeline.errors` 迁到 `errors/agent_aborted.py`。
- **注册方式换成「返回注销函数」**：`HandlerRegistry` 的 11 对 `on_<事件>()` / `remove_<事件>()` 合并成一个 `on(event, func, priority=0)`；事件名从 `miaoli_bot.consts` 的 11 个常量取。13 个内置子插件全部改成 `self.undo_list.append(registry.on(事件常量, ...))`，`on_close` 遍历 `self.undo_list` 逐个调用；`store_set()` 同样返回注销函数，原 `store_drop()` 的收尾一并取消。
- **工具注册链路**：子插件不再 `api.get_tool_registry()` 直接拿注册器，改 `api.register_tool()`；跑图入口每轮用 `ToolRegistry.to_surface()` 生成一份 `ToolSurface` 放进 `runtime.context["tool_surface"]`，`call_llm`（`bind_tools`）、`invoke_tools`（`ToolNode`）、`pick_tools`（按权限 `delete`）、`inject_mcp_tools`（去重后 `add`）全部改读快照。
- **消息入口改通道**：`main.py` 的 `@registrar.on_message` 整块删除。`on_load` 仍在连 checkpointer、装配共享容器、建 `Loader` 与 `Job(run_graph, Every(timedelta(seconds=60)))`，但不再注册任何消息处理器；`prepare_plugins()` / `load_plugins()` / `auto_waker.launch()` 挪到 `@registrar.on_startup()`（监听已在 `_startup_core()` 里起好，此时装子插件不会漏事件），末尾 `MAIN_READY.set()`。`run_graph` 每轮从 `ChannelRegistry.to_surface()` 取快照、按 `config.channel.drain_timeout` 并发 `batch_drain` 取空各通道，过滤空渠道后把结果 JSON 化作为 `raw_input` 进图；`AgentAborted` / 其它异常只打日志。
- **执行锁从「每会话一把」改成全局单例**：`INVOKE_LOCKS` → `INVOKE_LOCK`，`main.py` 的 `Dict[str, asyncio.Lock]` → `asyncio.Lock()`；`api/lock_ops.py` → `api/sync_ops.py`，`get_invoke_lock()` 语义不变，另增 `wait_main_ready()`（`await SHARE_STORE.recall(MAIN_READY).wait()`）。
- **`GraphState`**：`event: UntrackedValue` / `final_answer: UntrackedValue` → `raw_input: UntrackedValue`。
- **`GraphRuntimeContext`**：`tools: List[BaseTool]` → `tool_surface: ToolSurface`，`event` 字段删除。
- **根配置**：`account` / `split` / `typing` 三段从 `PluginConfig` 删除（账号注入迁出、发送侧下线），新增 `channel` 段；`check_pointer.py` → `checkpointer_config.py` 且 `CheckPointerConfig` → `CheckpointerConfig`；`plugin.py` → `plugin_config.py`、`provider.py` → `provider_config.py`、`sub_plugin.py` → `sub_plugin_config.py`（类名不变）。
- **`Plugin` 生命周期四步合成两步**：原 `load()`（建包 / 实例化 / 注入）、`activate()`（转发 `on_load`）、`deactivate()`（转发 `on_close`）、`unload()`（清 `sys.modules`）→ `async load()`（建包 + 实例化 + 注入 + `on_load`）与 `async unload()`（清 `sys.modules` + `on_close`）。`register_module()` / `unregister_module()` 两个模块级函数取消，清理逻辑内联进 `unload()`。
- **`Loader` 换成实体状态机**：三个只读属性 `prepared` / `loaded` / `erred` 与六个 `mark_*` 方法 → `entities: List[PluginEntity]`、`entity_mapping`（插件名 → 登记行）、`status`（按 PREPARED / LOADED / UNLOADED / ERRED 分批）；加载失败按 `PluginEntity` 判依赖是否跳过，回滚用 `await plugin.unload()`。
- **`api/store_ops.py`**：`store_set(key, value)` 不再因键已存在而 `KeyError`，改为打一行 warning 并返回注销函数（判实例相同才 `drop`）；`store_drop()` 与 `store_update()` 删除。`store_recall()` / `store_contains()` 不变。
- **`utils.easier_send`**：签名 `(ncatbot_api, chat_id, message, to_group=False)` → `(mode: Literal["group", "private"], chat_id, ob11_message: List[Dict], ncatbot_api=None)`，`ncatbot_api` 缺省时从 `SHARE_STORE` 取；`private_easier_send()` / `group_easier_send()` 两个分方向封装删除，只留合并后的一个入口。
- **`plugins/base_nodes`**：`latest_to_answer` 节点删除，`output_checker` 独占 `ON_AGENT_END`（`LOWEST`）；`call_llm` 每次请求打一行 token 用量日志（输入 / 命中缓存 / 未命中 / 输出 / 消息数 / 工具数）。

## Note

- **破坏性 API 清单**：仓库外自定义子插件若仍在调 `HandlerRegistry.on_<事件>()` / `remove_*()`、`ToolRegistry.remove(name, ignore_error=True)`、`api.get_tool_registry()`、`api.get_admin_id()` 等账号四件套、`utils.private_easier_send` / `group_easier_send`、`api.store_drop` / `api.store_update`，升级后会 `AttributeError` / `ImportError`。注册改 `registry.on(事件常量, func)` + `self.undo_list`、工具改 `api.register_tool()`、存储改 `api.store_set()`（返回注销函数）。
- **群聊 @ 过滤没了**：`on_message` 里原本有「群消息没 @ 到 `account.bot_id` 就跳过」这一道闸，它随 `on_message` 一起删除；新的入口链路里没有等价实现（`miaoli_qq_channel` 的 `QQChannel.drain()` 只取空缓冲，不做 @ 判定）。`account` 段也已删除，没有地方再声明 `bot_id`。
- **发送侧整体下线**：主包不再有「自动发送最终回复」的路径 —— `GraphState.final_answer` 删除、`split` / `typing` 两段配置删除、`event.reply` / 切块 / 打字延迟都没有消费者。模型要说话必须调用发送工具（由通道插件 `miaoli_qq_channel` 的 `qq_platform_tools` 提供），最终文本只进日志。写死「自动发送正文」的自定义节点会静默失效。
- **权限不再区分身份**：一张图同时服务多个通道、多个会话，节点拿不到「这一轮是谁在说话」，所以 `tool_permission_manager` 改成全局二值表。`bash` / `write` 这类危险工具要靠 `refuse` 显式列出才不会被放行（仓库内模板已按此写法）。未配置的工具默认摘除、`debug: true` 时打 warning。
- **意图注入会留痕**：`intent_recognition` 命中后追加的是普通 `HumanMessage`，走 `add_messages`，会永久留在历史与 checkpoint 里；未命中时返回 `None` 什么都不加。这一点与改版前「每轮覆盖 `prompts` 的 `intent-recognition` 段、不命中即置空」的语义不同 —— 连续命中会让上下文变长。
- **意图读取不再兜异常**：文件在加载后被删或编码不对会直接抛出去（改版前只让该 matcher 失效并打 `ERROR`）。要兜底得在读取处包一层。
- **旧会话的 checkpoint**：`event` / `final_answer` 两个通道已从 `GraphState` 移除，新 schema 不再声明它们，代码里也没有迁移逻辑；升级前建立的会话里这部分残留数据不会再被读取。要干净就清一次会话。
- **`ChannelSurface` 是一次性对象**：`__init__` 时就按通道名重建字典冻结引用，`batch_drain` 只能对一个快照调用一轮；要取第二轮就重新 `to_surface()`。
- **`drain_timeout` 只作用于单通道**：`batch_drain` 内部对每个通道各套一个 `wait_for`，超时或异常只落在自己那一路，由 `main.py` 打日志后当空渠道过滤。
- **`tests/` 依赖目录布局**：`pytest.ini` 的 `pythonpath = ..` 假定 `miaoli_bot` 与 `miaoli_qq_channel` 是 `plugins/` 下的兄弟包；换布局要同步改这一行。
