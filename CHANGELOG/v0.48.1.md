# v0.48.1 - 2026-11-11

> 🎚️ **优先级不再做加法**。`NORMAL + 1` / `NORMAL+2` 这类写法用「偏移量」表达「比默认早一点」，但九档阶梯里每一档本来就是为这件事准备的：偏移量既不能跨档比较（`NORMAL+2` 到底是哪一档？），也让「谁跟谁同档」变成隐式的注册顺序依赖。这一版把六处偏移量换成档位常量，事件内的执行顺序逐一比对过，与改动前完全一致。

## Changed

| 处理器 | 事件 | 改前 | 改后 |
|---|---|---|---|
| `inject_soul` | `ON_TURN_START` | `NORMAL + 1` | `MEDIUM`(10) |
| `inject_output_protocol` | `ON_TURN_START` | `NORMAL + 1` | `MEDIUM`(10) |
| `time_inject` | `ON_BEFORE_REQUEST` | `NORMAL + 2` | `MEDIUM`(10) |
| `build_prompt` | `ON_BEFORE_REQUEST` | `NORMAL + 1` | `NORMAL`(0) |
| `pick_tools` | `ON_BEFORE_REQUEST` | `1`（字面量） | `LOW`(-10) |
| `fix_pending_tool_call` | `ON_REQUEST` | `NORMAL+2` | `MEDIUM`(10) |
| `fix_orphan_tool_message` | `ON_REQUEST` | `NORMAL+2` | `MEDIUM`(10) |

改动涉及 `time_injector` / `prompt_builder` / `tool_permission_manager` / `orphan_tool_fixer` / `pending_tool_fixer` / `miaoli_bot_adapter` 六个子插件的 `main.py`：注册行换常量，`import` 跟着调整（`orphan_tool_fixer` / `pending_tool_fixer` / `miaoli_bot_adapter` 删掉不再使用的 `NORMAL`，另三个补上 `MEDIUM` / `LOW`）。

- `build_prompt`(0) 与 `pick_tools`(-10) 原本同为 `1`，先后由插件加载顺序决定；现在分成两档，顺序固定为 `build_prompt` 先 —— 与改动前实测顺序一致，但不再依赖加载顺序。两者操作的字段不同（一个写 `messages[0]`、一个摘 `tool_surface`），语义上也不存在反向依赖。
- 换档后各事件的 tier 序列：`ON_TURN_START` 为 `MEDIUM` / `MEDIUM` / `NORMAL` / `MINIMUM`，`ON_BEFORE_REQUEST` 为 `HIGH` / `MEDIUM` / `NORMAL` / `LOW` / `MINIMUM`，`ON_REQUEST` 为 `MEDIUM` / `MEDIUM` / `NORMAL` / `MINIMUM`，`ON_AGENT_START` 为 `MEDIUM` / `NORMAL` / `NORMAL` / `NORMAL` / `MINIMUM`。

## Removed

- `manifest.toml` 的 `pip_dependencies` 删掉 `pillow`（`>=12.3.0`）与 `tiktoken`（`>=0.14.0`）：两者的唯一引用方是 0.48.0 删除的 `context_compactor`（`image_to_tokens` 的图片宽高解析、`calculate.mode: tiktoken` 的精确计数），全仓已无 `import PIL` / `tiktoken`。依赖数量 20 → 18。

## Note

- **行为等价**：六个子插件的注册优先级数值都变了，但每个事件内的执行顺序逐一比对过（改前 / 改后各跑一次完整加载，比对事件内 handler 名称序列），八个事件全部一致。因此这一版不改变任何运行时行为，只是把「偏移量」换成「档位」。
- **`intent_recognition/main.py` 的一行注释**：原文写「必须早于 `prompt_builder` 的 `NORMAL + 1`（数值大者先跑）」，但两者不在同一个事件上，跨事件比 priority 本就没有意义（此说法 0.43.0 之后就已经过时）。改为「与 `prompt_builder` 不在同一个事件上，跨事件比 priority 没有意义；先后由 `default_routing` 的跳转决定」。
