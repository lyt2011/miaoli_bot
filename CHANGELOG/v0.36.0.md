# v0.36.0 - 2026-11-02

> 🧱 **压缩提示词从文件搬进代码，并在判定阈值时先把它计入 token**。`prompts` 各段的键名统一改成连字符（键名即 XML 标签名）。

压缩提示词原本只存在于 `data/compact_prompt.md`，靠 `compact.prompt_file` 的绝对路径引入：换部署环境（`/sdcard` ↔ `/root`）必须改配置，路径写错会让配置校验失败、插件直接加载不起来。搬到代码里之后默认值随包走，`prompt_file` 降级成可选的覆盖项。

守卫原本只对 `messages` 估算 token，压缩提示词本身（514 字符）不计入 —— 而压缩请求是 `[*messages, HumanMessage(prompt)]`，等于「按不含提示词的体积判断不压，再带着提示词的体积发请求」，极限情况下正好溢出。现在判定前先把提示词作为一条 `HumanMessage` 并入待算消息。

段名统一为连字符是顺带的：`build_prompt` 直接拿 `prompts` 的键拼标签，键名就是标签名，所以这一步等于全仓标签风格统一。

## Added

- `plugins/context_compactor/utils/prompt_ops.py`：新增 `DEFAULT_PROMPT` 与 `read_compact_prompt()` —— 每次调用重读、不缓存；`compact.prompt_file` 指向的文件存在时读它，否则回落到 `DEFAULT_PROMPT`；返回值用 `<compact-request>` 包裹。

## Changed

- `plugins/context_compactor/nodes/should_compact.py`：估算 token 前把压缩提示词以 `HumanMessage` 追加进待算消息。
- `plugins/context_compactor/nodes/compact.py`：压缩请求的提示词改用 `read_compact_prompt()`。
- `plugins/context_compactor/models/compact_config.py`：`prompt_file` 类型由 `FilePath` 放宽为 `Path` —— 文件不存在不再让配置校验失败；删除 `_prompt` 的 `PrivateAttr` 与懒加载 `prompt` property。
- **`prompts` 段名统一为连字符**：`current_time` → `current-time`、`intent_recognition` → `intent-recognition`、`output_protocol` → `output-protocol`、`account_info` → `account-info`、`meme_helper` → `meme-helper`、`available_memes` → `available-memes`（`soul` 与 `<abstract>` 本身是单词，不变）。
- 文档：主 README 中英双份与 6 个子插件 README 同步段名；`context_compactor/README.md` 与 `config.example.yaml` 改为「提示词内置，`prompt_file` 可选」。

## Removed

- `plugins/context_compactor/data/compact_prompt.md`：内容并入 `utils/prompt_ops.py` 的 `DEFAULT_PROMPT`。

## Note

- `prompts` 是会写进 checkpoint 的通道，段名改动对**升级前就已存在的会话**表现不同：旧键的值停在升级前的最后一次写入，新键每轮照写，同一个语义会在系统提示词里出现两份（`output-protocol` 整份重复、`intent-recognition` 停在上一次的命中内容）。清一次会话即消除，升级后新建的会话不受影响。
