# v0.35.1 - 2026-11-02

> 🔧 **修掉客户端切换带出的运行时错误**。0.35.0 把 `get_model_info()` / `get_provider_info()` 改成直接返回 `LLM` / `Provider` 实例，但唯一消费方 `should_compact` 仍按下标取值，于是每一轮的压缩守卫都会抛 `TypeError`；同一批改动里 `ensure_pm_exist` 的 `model` 分支还漏了 `raise`，配错的模型名能通过启动校验。这一版把两个返回值改回 `dict`，补上 `raise`，并让 `build_prompt` 在提示词为空时不再注入。

## Changed

- **`build_prompt` 的提示词段按 `sorted()` 稳定排序**后拼接，不再依赖 `prompts` 字典的插入顺序 —— 先删后写的段不会再被挪到末尾，各轮拼接顺序一致，前缀缓存不再随写入时序抖动。
- **`build_prompt` 的返回值注解**由 `Dict[str, Any]` 改为 `Optional[Dict[str, Any]]`（该节点会 `return None`）。

## Fixed

- **`api.get_model_info()` / `api.get_provider_info()` 恢复返回 `dict`**（`model_dump()`）：0.35.0 改成返回实例后，`context_compactor` 的 `should_compact` 仍然按 `model_info["max_tokens"]` / `["context_window"]` 取值，`enable` 为真的每一轮 `on_before_compact` 都抛 `TypeError: 'LLM' object is not subscriptable`。子插件只需要两个整数，不需要跟配置实例耦合。
- **`models/config/plugin.py` 的 `ensure_pm_exist` 补上 `raise`**：原本 `ValueError(...)` 只被构造、没有抛出，`model` 名字写错也能通过启动校验，错误被推迟到第一次建客户端（表现为 `ModelNotFound`，或 `get_model_info()` 返回 `None` 后的 `AttributeError`）。
- **`build_prompt` 在 `prompts` 为空时整段跳过注入**：`prompt_string` 为空串时直接 `return None`，不再写入一条 `content` 为空的 SystemMessage，也不再每轮 `Overwrite` 一遍整张消息表。

## Note

- **`build_prompt` 仍是 SystemMessage 的唯一写入点**：历史中其他位置出现的 SystemMessage 会被丢弃，保证发给模型的消息列表里有且只有一条系统提示。
- **悬空 `tool_call` 的重复 id / 位置错乱未处理**：`pending_tool_fixer` 目前只按「该 id 是否在历史中出现过」判断，不检查返回是否紧跟在发起它的 `AIMessage` 之后。这块留给后续的修复插件，主包字段不变，新旧插件互相兼容。
