# v0.25.0 - 2026-10-20

> 🧱 **`meme_ops` 配置拆成 `database` / `help_doc` 两个子配置**。`PluginConfig` 此前把启用开关、数据库路径、帮助文档路径与编码平铺在同一层，四组参数各管一摊，读配置看不出层级。节点同时改名 `inject_helper` → `inject_doc`。

`PluginConfig` 收窄为三个字段：

```python
class PluginConfig(BaseModel):
	enable		: bool				= ...
	database	: DatabaseConfig	= ...
	help_doc	: HelpDocConfig		= ...
```

`DatabaseConfig` 收 `path`（sqlite 数据库路径），`HelpDocConfig` 收 `path` + `encoding`（表情包扩展帮助文档与其编码）。

节点名跟着它注入的内容走 —— 它注入的是一份帮助文档，`inject_helper` 这个叫法说的是「注入一个帮手」，与「把 `help_doc.path` 的文件内容写进 `meme_helper` 段」这件事对不上，改成 `inject_doc`，文件名同步（`nodes/inject_helper.py` → `nodes/inject_doc.py`）。

同时删掉 `PluginConfig.helper` 这个懒加载属性。它每次访问都读一次文件，读的又是 `helper_path` + `encoding` 这两个字段 —— 字段搬进 `HelpDocConfig` 后，这个属性留在 `PluginConfig` 上就成了跨层访问，直接让 `inject_doc` 自己从 `help_doc` 子配置里读。

## Changed

- `models/plugin_config.py`：`PluginConfig` 收窄为 `enable` / `database` / `help_doc`（破坏性 —— 旧的扁平写法不再被识别）。
- `models/database_config.py`（新增）：`DatabaseConfig`，字段 `path`。
- `models/help_doc_config.py`（新增）：`HelpDocConfig`，字段 `path` / `encoding`。
- `models/__init__.py`：补导出 `DatabaseConfig` / `HelpDocConfig`。
- `models/plugin_config.py`：`check_db_path` 与 `check_helper_path` 改读 `self.database.path` / `self.help_doc.path`；后者改名 `check_doc_path`。
- `nodes/inject_helper.py` → `nodes/inject_doc.py`：函数改名 `inject_doc`，注入内容改从 `store_recall(PLUGIN_CONFIG).help_doc` 取路径与编码自行读文件。
- `nodes/__init__.py` / `main.py`：导入与注册同步 `inject_doc`。
- `tools/*.py`：5 个工具取数据库路径由 `.db_path` 改为 `.database.path`。
- `config.example.yaml`：按新结构重排为 `enable` / `database.path` / `help_doc.path` + `help_doc.encoding`。

## Removed

- `models/plugin_config.py`：`helper` 属性（每次访问读文件，字段搬进 `HelpDocConfig` 后属跨层访问）。

## Fixed

- `nodes/inject_doc.py`：补 `Path` 导入。

## Note

- `meme_helper` 段名没改。它指「表情包帮助」这件事，与节点名 `inject_doc` 不冲突。
- `help_doc` 的文件内容仍不缓存，每次注入读一次。662 字节，开销可忽略。
- 已有部署必须同步改 `config.yaml` 为嵌套结构 —— 旧扁平键会被 pydantic 静默忽略，`database.path` 与 `help_doc.path` 双双为 `None`，`check_db_path` 直接 `ValueError`。
