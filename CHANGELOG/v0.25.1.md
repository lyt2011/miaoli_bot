# v0.25.1 - 2026-10-21

> 🧱 **新增 `intent_recognition` 子插件：按规则识别意图，命中就把对应提示词注入 `prompt`**。规则全在配置里，加一种命中方式 = 加一个配置类，节点不用动。

一个 matcher 的多条 rule 是**「与」关系** —— `all()`，有一条不满足就整体不命中。命中后按 `encoding` 读 `file`，以 `name` 为键；所有命中项最后合成**一个**段（段名固定 `intent_recognition`），`matcher.name` 只是段内子标签。

```
<intent_recognition><meme>…</meme>
<privacy>…</privacy></intent_recognition>
```

待匹配文本由纯函数 `get_content` 提取，参数类型是 `Any` —— 鸭子类型地读 `content`，不依赖具体消息类。它只收两种块：带 `str` 型 `text` 键的字典块、裸字符串块；图片块与 `tool_use` 块一律跳过。绕这一层是因为直接 `str(content)` 会拿到 Python 的 repr，把 `image_url` 的 base64 data URL 一起带进待匹配文本，关键词和正则会在 base64 随机串上误命中。

`enable` 默认 `false`，关闭时节点不注册，现有部署不受影响。

## Added

- `plugins/intent_recognition/`：新的内置子插件。
- `models/plugin_config.py`：`PluginConfig` 收 `enable`（默认 `false`）与 `matchers`。
- `models/match_.py`：`Match` 收 `name` / `file`（`FilePath`）/ `encoding`（默认 `utf-8`）/ `rules`（至少 1 条）；`Rule` 是 `KeywordsRule` / `KeywordRule` / `RegexRule` 以 `mode` 为判别字段的判别式联合。
- `models/rules/`：三种命中方式 —— `KeywordRule`（`word in data`）、`KeywordsRule`（`words` 命中数量 `>= count`，`count` 默认 1）、`RegexRule`（`re.search`，编译结果缓存进 `PrivateAttr`）。
- `protocols/rule.py`：`BaseRule(ABC)`，抽象方法 `is_hit(data: Any) -> bool`。
- `nodes/recognize_intent.py`：`recognize_intent` 挂 `on_before_request`，`priority=NORMAL`。
- `utils/helper.py`：`build_prompt`（把字典拼成 `<key>value</key>`）/ `get_content`（多模态正文提取）。
- `config.example.yaml` + `README.md`。

## Note

- `priority` 必须是 `NORMAL`（小于 `prompt_builder` 的 `NORMAL + 1`），否则拼装时读不到本轮写入的段。
- `file` 是 `FilePath`，路径不存在会在**加载期**抛 `ValidationError`，到不了节点；节点里的 `try/except` 兜的是「加载时文件在、之后被删」「编码不对」「正则非法」这类运行期失败，只让当前 matcher 失效并打 `ERROR` 日志，不影响其它 matcher。
- 全字段 `extra="forbid"`：键名拼错直接报错，不会被静默忽略。每条 rule 必须显式写 `mode` —— 它是判别字段，省略不会被默认值兜底。
- `BaseRule` 是纯 ABC 却能把 `model_config = ConfigDict(extra="forbid")` 传给三个 pydantic 子类：pydantic 会从非 `BaseModel` 的基类 `__dict__` 里收集 `model_config`，所以挂在 `BaseRule` 上一处即可。
- 没命中时该段被置为**空字符串**而不是删除，`prompt_builder` 会渲染出一个空的 `<intent_recognition></intent_recognition>` —— 好处是上一轮命中的内容不会残留。
