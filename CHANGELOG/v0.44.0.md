# v0.44.0 - 2026-11-10

> 🧱 **平台对称性交给框架，别再往 `thread_id` 里编码路由**。上一版 `reply(thread_id, text)` 的签名有个隐含约定：会话标识必须自己带着「这是哪个平台」的信息，通道靠解析字符串前缀反推怎么发。可 `thread_id` 本来只是**会话**的身份，把平台塞进去等于让每个通道各自发明一套编码，主包没法校验、也没法拒绝。
>
> 这一版把平台提成一等公民：通道自报 `platforms`，每条消息带自己的 `platform`，主包原路带回。什么东西进来就什么东西出去，框架负责对不上就报错。
>
> 顺带删掉 `to_text()`：它的三个「用途」（日志 / 去重 / 判定）一个都不存在，而日志真正需要的是一个 `__str__`。
>
> 破坏性变更三处：`BaseChannelMessage.to_text()` 删除、`BaseChannel.reply` 换签名、`BaseChannel` 多一个抽象成员 `platforms`，所以 minor 升到 0.44。

## Added

- `Content`（`protocols/channel/message.py`）：`Union[str, List[Dict[str, Any]]]` —— 一条消息正文的两种形态。提成模块级别名是为了让 `to_content()` 的返回值和 `reply()` 的入参用**同一个类型**，不再各写一遍。`protocols` 与 `protocols.channel` 两层都导出它。
- `BaseChannel.platforms`（抽象属性，`FrozenSet[str]`）：通道自报能收发哪些平台。主包拿它和每条消息自带的 `platform` 做对称路由。
- `BaseChannelMessage.__str__`：基类给具体实现，输出 `<类名 平台:会话>`。**实现里不许调 `to_content()`** —— 多模态之后那是 base64，而 `logger.debug(...)` 会无条件求值。

## Changed

- `BaseChannel.reply()` 的签名从 `reply(thread_id: str, text: str)` 改成 `reply(platform: str, thread_id: str, content: Content)`：平台显式传入，正文类型与 `to_content()` 对齐 —— 模型回字符串就是字符串，回内容块列表就是块列表，通道自己决定认不认。
- `main.py` 的跑图入口：`HumanMessage` 现在挂 `additional_kwargs={"platform": message.platform}`。平台跟着消息进图，出图时直接读回来，不用再到别处查。
- `main.py` 的回发分支：`channel.reply(message.thread_id, messages[-1].content)` 改成 `channel.reply(message.platform, message.thread_id, last.content)`，同时把 `match` 的分支从「取列表末尾再判类型」收成 `case {"messages": [*_, last]} if isinstance(last, AIMessage)`。
- `main.py` 的空消息判据从 `message.to_text().strip()` 改成 `to_content()`：空字符串判 `.strip()`，空列表直接判假。块列表（只带图片的消息）不再被误当成空值。

## Removed

- `BaseChannelMessage.to_text()`：抽象成员连同所有调用点一起删。查过全仓，它列出来的三个用途都是空的 —— 日志不需要它（改用 `__str__`），去重没有实现，判定逻辑在 `miaoli_qq_channel` 那边且已经删掉了。

## Note

- **平台不参与路由编码**。`thread_id` 只表示会话（`group-<群号>` / `private-<QQ号>`），通道想支持几个平台就在 `platforms` 里报几个，主包只保证「进来的 `platform` 原样交回去」。通道自己校验不认识的平台属于通道的责任。
- **`platforms` 漏实现会在加载阶段炸**（ABC 会拦），但 **`reply` 签名没跟上只会在第一次真正回话时炸** —— Python 的 ABC 只检查「名字被覆盖」，不校验签名。所以主包和通道必须同窗口上线，不能靠「加载成功」判断兼容。
- 日志里的纯文本视图如果确实需要，用现成的 `content_to_text` / `block_to_text`（`plugins/intent_recognition/utils/sugar.py`），不必再给协议加一个方法。

## Docs
